# PLT-004: Run A Local Development Room

# What

- Add one local development command that starts the browser client and a
  loopback-only simulated coordinator on an IdeaPad.
- Keep the normal coordinator HTTP and server-sent event contract, while using
  deterministic in-memory room state rather than the ThinkPad, iMac, Hue,
  Spotify, weather service, or production voice runtime.
- Make ordinary UI and action work fast to test before physical deployment.

## Out Of Scope

- Replacing final ThinkPad, iMac, Sonos, Hue, Spotify, camera, AirPlay, alarm
  wake, or room-voice confirmation.
- Adding a generic mock framework, second frontend, or runtime configuration
  system.
- Altering the production coordinator installer or installed service.

## Dependencies

- The local client continues to use Vite's existing `/api` proxy.

# Acceptance Criteria

- [ ] One documented command starts the development room on loopback and stops
  both local processes when it exits.
- [ ] Client source changes hot-reload without uploading anything to the
  ThinkPad or iMac.
- [ ] The local coordinator uses the production `/api` and SSE contract.
- [ ] A deterministic normal scenario renders available Today, Music, Lighting,
  and Alarm state; normal channel and scene actions complete against simulated
  state.
- [ ] A deterministic unavailable scenario renders the corresponding empty or
  unavailable presentation without contacting room services.
- [ ] The local voice path accepts the normal browser capture shape and returns
  fixed local answer audio without a provider key, model download, or room
  hardware.
- [ ] Camera remains a browser-local permission flow on `localhost`; AirPlay,
  sleep, and endpoint audio controls honestly show unavailable because no iMac
  bridge exists.
- [ ] The development runtime is loopback-only, keeps no durable state, and is
  not copied by the production installer.
- [ ] Automated checks cover deterministic scenarios, scene completion, local
  voice collaborators, launcher cleanup shape, and the no-production-payload
  boundary.

# Approach And Decisions

- Reuse `Coordinator` and `CortexHomeServer`; inject only small in-memory
  collaborators from a development-only entry point. This exercises the real
  browser boundary without placing development code in the production payload.
- `./coordinator/develop` starts the loopback coordinator and Vite as child
  processes, then waits for Vite. Its exit trap stops both children.
- Support exactly two fixed scenarios: `room` for normal presentation and
  `unavailable` for degraded states. Browser keyboard actions remain the way to
  navigate and exercise actions.
- The fixed development recognizer, answer, and short WAV exist only to test
  the capture, feedback, completion, and failure lifecycle. They are not an
  alternative speech implementation.

# Implementation Walkthrough

1. `coordinator/development.py` is the development-only entry point. It binds
   only `127.0.0.1:8080`, composes the ordinary `Coordinator` and
   `CortexHomeServer`, and never starts the production Hue or Today adapters,
   production speech runtime, Node child, or any endpoint helper.
2. Its `room` scenario publishes fixed available Today, Music, Lighting, and
   disarmed Alarm snapshots. The in-memory lighting collaborator reports the
   requested scene as active, so the ordinary scene request lifecycle
   completes. Its `unavailable` scenario publishes the corresponding degraded
   snapshots and has no scene collaborator.
3. The development recognizer, agent, and synthesizer accept the existing
   browser WAV shape and return one fixed response with a short generated WAV.
   They make the browser feedback lifecycle testable without credentials,
   models, providers, or room devices.
4. `coordinator/develop` runs that coordinator and the existing
   `pnpm --dir coordinator/client dev` command as children. It verifies
   coordinator startup, waits for Vite, and its exit trap stops and reaps both
   child processes. It accepts `--scenario unavailable` for degraded UI work.
5. Install client dependencies once, then use the following commands from the
   repository root:

   ```sh
   pnpm --dir coordinator/client install --frozen-lockfile
   ./coordinator/develop
   ```

   Open `http://127.0.0.1:5173`. Use this instead for unavailable and empty
   presentation work:

   ```sh
   ./coordinator/develop --scenario unavailable
   ```

   Press `Control`+`C` in the terminal to stop the local coordinator and Vite.
   Neither command deploys files, needs an SSH tunnel, nor changes coordinator,
   endpoint, or room configuration.
6. `coordinator/tests/test_development.py` keeps the fixed scenario, local
   voice, loopback bind, launcher, and production-deployment boundary covered.
   The production coordinator Ansible role omits both development entry points.

# Problems Encountered

- Symptom: The agent package tests initially could not resolve their pinned
  dependencies in this new worktree.
- Diagnosis: Dependencies are isolated per worktree and had been installed only
  in another checkout.
- Resolution: Ran `pnpm --dir coordinator/agent install --frozen-lockfile`
  before the agent checks. No project files changed.
- Remaining caveat: A new worktree needs the documented client installation;
  agent dependencies are needed only when running the separate agent checks.
