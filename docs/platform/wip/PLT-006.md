# PLT-006: Add A Deployment Entry Point

# What

Provide one small operator-facing command for the existing Ansible deployment
flow.

Before:

Operators had to activate the Ansible virtual environment, enter `ops`, and
invoke the playbooks manually.

After:

`./deploy` creates the local Ansible environment when needed, creates the
ignored inventory from the example when needed, checks SSH connectivity, and
delegates coordinator and endpoint convergence to the existing playbooks.

## Out Of Scope

- Changing Ansible roles, host desired state, secrets, or deployment prompts.
- Replacing Ansible with a custom provisioning implementation.
- Automatically editing private inventory values or committing them.

# Heatmap

## Warm - Keep The Wrapper Thin

- **Decision** - Keep `deploy` as a shell entry point over the existing
  playbooks.
- **Why** - Operators get a short, repeatable command while Ansible remains the
  authority for privileged host state.
- **Alternatives** - Duplicate provisioning in shell or require every
  operator to use the lower-level Ansible commands.

# How to test

### Wrapper validation

- **Start** - Use a checkout with no `.venv-ansible` or `ops/inventory.yml`.
- **Action** - Run `./deploy --help`, `./deploy setup`, and `./deploy all` with
  reachable private inventory.
- **Expected** - The environment and ignored inventory are created, SSH is
  checked, and the coordinator playbook completes before the endpoint
  playbook.

### Focused deployment

- **Start** - Use an already provisioned endpoint.
- **Action** - Run `./deploy imac --tags media`.
- **Expected** - The endpoint media tag is converged using the existing sudo
  prompt and no coordinator deployment is attempted.

# Notes

- The wrapper accepts additional Ansible options after each deployment command,
  such as `--tags media`, `--check`, and `--limit imac`.
- `./deploy all` always runs the coordinator before the endpoint so the client
  and endpoint configuration stay aligned.
- `sh -n deploy` passed, both Ansible playbooks passed syntax checks against the
  example inventory, the endpoint suite passed with 26 tests and 3 skips, and
  the coordinator suite passed with 149 tests.
- No physical host was contacted during these checks.
