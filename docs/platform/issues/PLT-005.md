# PLT-005: Consolidate Host Provisioning

# What

Replace the growing collection of paired local and remote shell installers with
one repository-owned Ansible layout for the ThinkPad coordinator and iMac
endpoint.

Before:

Each deployment concern has a local SSH/SCP wrapper and a separate privileged
host script. Full and focused endpoint installers repeat package, file, service,
and validation logic, and tests inspect shell source text to keep the copies in
sync.

After:

Ansible playbooks build and deploy the coordinator and converge the iMac's
base, media, Raspotify, and alarm state through shared roles. Inventory and
secrets remain outside Git. Interactive application operations and installed
runtime helpers remain small executable commands.

## Out Of Scope

- Changing the coordinator, browser, endpoint, or room behavior.
- Storing host addresses, SSH credentials, Wi-Fi credentials, provider keys, or
  private room evidence in Git.
- Making Codex or any other automated process the authority for unrestricted
  remote root access.
- Replacing endpoint runtime helpers with another language solely to remove
  shell syntax.

# Heatmap

## Hot

### H1 - Use Ansible Only For Host Desired State

- **Decision** - Put packages, accounts, files, permissions, and services in
  Ansible while retaining interactive product operations and endpoint runtime
  helpers as executable commands.
- **Why** - This removes installer duplication without hiding narrow product
  operations inside a general deployment framework.
- **Alternatives** - Keep all shell installers; replace every command with a
  custom deployment CLI; containerize host-integrated endpoint services.

### H2 - Keep Private Deployment Values Outside Git

- **Decision** - Commit an inventory example and prompt for first-install
  secrets with hidden Ansible prompts. Preserve existing secret files on later
  runs.
- **Why** - Reproducible host state does not require repository-owned home
  addresses or credentials.
- **Alternatives** - Commit encrypted secrets; require fixed repository host
  aliases; provision secrets separately by hand.

# How to test

### Static provisioning

- **Start** - Install the pinned repository Ansible requirements in an isolated
  environment.
- **Action** - Run syntax checks for every playbook and the repository's
  provisioning unit tests.
- **Expected** - All playbooks parse, reference existing payloads, preserve
  reviewed versions and checksums, and expose the documented focused paths.

### Physical hosts

- **Start** - Create a private inventory whose coordinator and endpoint aliases
  are reachable through key-based SSH.
- **Action** - Deploy the coordinator, converge each focused endpoint playbook,
  and rerun them once.
- **Expected** - Services are active, the room behavior is unchanged, secrets
  are not printed, and the second run reports no unexpected changes.

# Notes

- `ops/playbooks/coordinator.yml` owns production deployment and exposes the
  isolated qualification workbench through `--tags speech`.
- `ops/playbooks/endpoint.yml` owns complete endpoint convergence and exposes
  `media`, `raspotify`, and `alarm` focused tags. Shared tasks remove the former
  full-versus-focused installer copies.
- Twelve paired local/remote installers were removed. The remaining shell
  executables are three operator workflows and ten installed endpoint runtime
  components.
- `ansible-core==2.21.3` is pinned for the controller. Both playbooks pass
  `--syntax-check`, expose the expected tags, and pass the `ansible-lint`
  production profile with no findings.
- The full coordinator suite passes 152 tests. The endpoint suite passes 23
  tests with three OpenBSD-netcat-dependent tests skipped on this host. The
  client passes static checks, 76 tests, and its production build. Remaining
  shell executables pass their `sh -n` or `bash -n` checks, and
  `git diff --check` reports no whitespace errors.
- Physical-host convergence remains reviewer confirmation after SSH access is
  configured for this workspace. No host was contacted during implementation.
- The first access attempt showed that this development host does not resolve
  `imac.local`, while its established `imac` SSH alias maps to the fixed local
  address. The inventory example now delegates both destinations to SSH aliases
  instead of requiring controller-side mDNS.
