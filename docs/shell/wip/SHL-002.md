# SHL-002: Evaluate Channel Transitions

Previous identifier: `GH-020`.

# What

- Evaluated snapshot and fade-through-black transitions on the low-end iMac,
  then restored reliable instant channel cuts.
- Added looped `Ctrl`+`Alt`+`Left` and `Ctrl`+`Alt`+`Right` channel requests.
- Added a global `Ctrl`+`Alt`+`M` iMac performance overlay with the shared
  loopback-bridge retry used by AirPlay, `Escape`, and a Close button.
- Recorded the performance findings and rejected architecture alternatives.

# Acceptance Criteria

- [x] Every observed channel change updates the React view immediately without

- [x] Camera, AirPlay, Music fullscreen, initial load, reconnect, failures, and
  rapid observations retain their existing direct behavior.
- [x] Exact non-repeating `Ctrl`+`Alt`+`Left`/`Right` shortcuts request the

- [x] The visible overview also closes through plain non-repeating `Escape` or

- [x] The local stats route remains loopback-only and bound to the configured
  coordinator origin; it exposes no host identity, processes, or history.
- [x] `docs/CHROMIUM_PERFORMANCE.md` records the measured outcome and explains

- [ ] The reviewer confirms the final deployed instant cuts, rapid switching,
  Camera/AirPlay boundaries, and performance overlay.

# Plan Diff

- The original plan proposed the View Transition API. The deployed Today/Music
  transition was visibly laggy on the iMac and did not cover all channels.
- A researched solid fade-through-black replacement was then implemented. Its
  first deployed sequencing path reported action completion but left the
  browser on Today.
- Although deterministic midpoint timers corrected that implementation locally,
  the user chose to remove channel animation entirely. Instant cuts are the
  final accepted behavior.
- The user added looped previous/next shortcuts, a performance overlay, and the
  durable Chromium performance note during this evaluation.

# Implementation Walkthrough

- `coordinator/client/src/App.jsx` listens for `channel.active`, updates the
  active-channel reference, exits Music fullscreen when required, and dispatches
  the snapshot directly. There is no transition component, overlay, timer,
  animation promise, or second channel tree.
- `coordinator/client/src/room-state.js` owns the four-channel order and maps
  exact `Ctrl`+`Alt`+`Left`/`Right` chords to the existing `channel.select`
  action. The coordinator remains the sole authority for the visible channel.
- `endpoint/imac/files/cortex-airplay-control` serves bounded `GET /stats`
  snapshots from Linux `/proc` and thermal sysfs through the existing
  loopback-only, origin-bound bridge. It retains no samples and introduces no
  process or package.
- `coordinator/client/src/endpoint-control.js` owns the one 75 ms retry needed
  when Chromium's private-network preflight falls into the one-connection
  netcat listener's replacement gap. The caller still owns its clear feature
  error message and no background retry is added.
- `coordinator/client/src/SystemStats.jsx` validates the response and renders a
  solid, no-blur overlay above the React shell. It requests immediately when
  opened, schedules a new request only after the prior one settles, and stops
  polling when hidden. `Ctrl`+`Alt`+`M`, plain `Escape`, and its Close button
  dismiss it.
- `docs/CHROMIUM_PERFORMANCE.md` records the snapshot cost model, framework
  research, failed transition outcomes, final instant-cut decision, and steps
  for any future hardware-specific investigation.
- For local development, run `pnpm --dir coordinator/client install` and
  `pnpm --dir coordinator/client dev`. Build and deploy the browser with
  `./coordinator/install <server-ssh-host>`. Install the updated endpoint bridge
  through `./endpoint/imac/provision-media`.

# Problems Encountered

## 1. Client dependencies were absent in this worktree

- Symptom: The initial client test command could not resolve React.
- Diagnosis: `coordinator/client/node_modules` had not been installed in this
  worktree.
- Resolution: Ran `pnpm install --frozen-lockfile`; the existing lockfile was
  already current and no dependency manifest changed.
- Remaining caveat: None.

## 2. View Transition snapshots lagged on the iMac

- Symptom: The swipe worked only between Today and Music and was visibly laggy.
- Diagnosis: Chromium captured and blended large old/new channel surfaces at
  the 1920×1200 kiosk resolution; Camera, AirPlay, and Music fullscreen were
  deliberately excluded for privacy and composition safety.
- Resolution: Researched lower-cost compositor approaches, rejected SSR and
  framework migration as unrelated to runtime compositing, and prototyped a
  solid black fade.
- Remaining caveat: Exact GPU allocation was inferred from the documented
  snapshot model rather than captured from the physical GPU process.

## 3. The black fade blocked the observed view update

- Symptom: The coordinator reported a completed channel change, but Chromium
  remained on Today.
- Diagnosis: The first fade controller gated the React dispatch on an animation
  completion promise that did not settle reliably on the deployed path.
- Resolution: Removed all transition sequencing and restored direct dispatch.
- Remaining caveat: None; animation is no longer part of channel correctness.

## 4. The performance overview exposed a raw fetch failure

- Symptom: Opening the monitor with `Ctrl`+`Alt`+`M` sometimes displayed
  `Failed to fetch` while the local bridge was running.
- Diagnosis: The stats request did not share AirPlay's retry for Chromium's
  private-network preflight and the bridge's one-connection listener gap.
- Resolution: Moved that one 75 ms retry into the shared endpoint-control
  request helper, added stats coverage, and documented the rule beside the
  bridge operator guidance.
- Remaining caveat: The bridge remains serial by design; the retry is bounded
  and is not a general reconnection policy.

## 5. A browser-only deployment cannot add endpoint stats

- Symptom: The deployed monitor did not receive any statistics.
- Diagnosis: The iMac was still running the pre-GH-020 bridge, which has no
  `/stats` route. A temporary run of the current bridge on the iMac returned
  valid CPU, memory, temperature, load, and uptime data.
- Resolution: Record that `/stats` requires `./endpoint/imac/provision-media`
  in addition to the browser deployment. The browser monitor now also has
  plain `Escape` and an on-screen Close button as independent dismissal paths.
- Remaining caveat: Endpoint provisioning restarts the kiosk session and must
  be scheduled around active use.

# Heatmap

## Hot

### H1 - Keep Channel Correctness Independent Of Motion

- Decision: Use direct observed-state dispatch and immediate cuts.
- Where: `coordinator/client/src/App.jsx`.
- Why: Both attempted transition paths made basic switching worse on the target
  hardware.
- Alternatives: View Transition snapshots; fade-through-black; incoming-only
  animation; retained parallel views; a rendering framework migration.

## Cold

| Where | What |
|---|---|
| `coordinator/client/src/room-state.js` | Map exact arrow chords to the fixed looped channel order. |
| `coordinator/client/src/SystemStats.jsx` | Validate and present bounded local performance data only while requested. |
| `endpoint/imac/files/cortex-airplay-control` | Serve one current loopback-only system snapshot without retaining telemetry. |

## Stylistic

### S1 - Instant Channel Cuts

- Choice: Replace channel content immediately after the coordinator observation.
- Alternative: Any animated channel handoff.
- When to apply: All channel changes on the current iMac endpoint.

# Notes

- The performance overview is available over every Chromium-rendered view.
  Native AirPlay video remains above Chromium by accepted Openbox policy.
- SSR and Astro are not recommended for this transition problem. They affect
  initial delivery and hydration rather than the runtime channel replacement.
