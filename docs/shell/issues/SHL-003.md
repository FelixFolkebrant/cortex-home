# SHL-003: Separate Frontend Channels

Previous identifier: `GH-026`.

# What

- Reorganized the browser client around explicit Today, Music, Camera, AirPlay,
  and Alarm channel directories.
- Separated application-shell, voice-interaction, diagnostics, and shared code
  from channel-owned files.
- Colocated Alarm, Camera, and Music styles and focused tests with the channel
  that owns them while preserving the explicit application switch and current
  behavior.

# Acceptance Criteria

- [x] Today, Music, Camera, AirPlay, and Alarm each have a named directory under
  `coordinator/client/src/channels/` containing their owned browser files.
- [x] The application shell, voice interaction, diagnostics, and shared endpoint
  control have distinct directories outside `channels/`.
- [x] `app/App.jsx` retains one explicit channel switch with no dynamic registry
  or routing abstraction.
- [x] Existing frontend checks, all 75 tests, and the production build pass
  without changing behavior.
- [x] The coordinator installer coverage still confirms that the client is
  built and staged from `coordinator/client`.

# Plan Diff

- The accepted plan deferred reducing both `App.jsx` and `room-state.js`. During
  the move, four pure Music-only helpers and their tests had an unambiguous
  owner, so they moved to `channels/music/music-state.js`. Stateful application
  orchestration remains deferred.

# Implementation Walkthrough

## 1. Keep The Application Shell Explicit

`coordinator/client/index.html` now loads `src/app/main.jsx`. The `app`
directory owns the React entry point, `App.jsx`, the room reducer and keyboard
navigation, its tests, and the stylesheet that composes global and channel
styles.

`App.jsx` still imports every channel directly and selects one with its existing
hard-coded conditional switch. No route table, registry, lazy loader, or plugin
contract was added.

## 2. Give Every Channel One Discoverable Home

`coordinator/client/src/channels/` contains one directory for each fixed product
view:

- `today/` owns the clock and weather presentation.
- `music/` owns normal and full-screen playback presentation, palette logic,
  playback state helpers, Music CSS, and focused tests.
- `camera/` owns local capture presentation, capture logic, Camera CSS, and
  capture tests.
- `airplay/` owns receiver presentation and endpoint-control requests.
- `alarm/` owns the alarm clock and editor presentation, editor logic, Alarm
  CSS, and editor tests.

The cross-channel rendering tests remain at `channels/channels.test.js` because
they intentionally exercise interactions among multiple views and overlays.

## 3. Keep Cross-Cutting Responsibilities Outside Channels

`voice/` owns browser capture, spoken interaction, the audio worklet, feedback
styles, and their tests. `diagnostics/` owns the optional system-statistics overlay.
`shared/` owns only the class combiner and the endpoint control request used by
multiple product areas.

The endpoint operations guide now points at
`coordinator/client/src/shared/endpoint-control.js`, its current source path.

## 4. Discover Colocated Tests Recursively

The client `test` script now runs `node --test` without the former
`src/*.test.js` argument. Node discovers the existing `*.test.js` files
recursively, so tests remain beside their owners without maintaining another
path list.

Install dependencies and verify the reorganized client from the repository
root:

```sh
pnpm --dir coordinator/client install --frozen-lockfile
pnpm --dir coordinator/client check
pnpm --dir coordinator/client test
pnpm --dir coordinator/client build
python3 -m unittest discover -s coordinator/tests
python3 -m unittest discover -s endpoint/imac/tests
```

For local presentation testing, forward the installed coordinator and start the
unchanged Vite entry point:

```sh
ssh -N -L 8080:127.0.0.1:8080 <server-ssh-host>
pnpm --dir coordinator/client dev
```

# Problems Encountered

## 1. The Previous Test Command Covered Only Flat Source Files

- Symptom: Moving tests beside their channel owners would place them outside the
  `src/*.test.js` path passed to Node.
- Diagnosis: Test discovery encoded the old flat directory layout in
  `package.json`.
- Resolution: Let the Node test runner discover `*.test.js` files recursively;
  the resulting run found and passed all 75 tests.
- Remaining caveat: New tests must retain Node's recognized `*.test.js` naming.

## 2. Moved Imports No Longer Matched The Accepted Ordering

- Symptom: The first Biome check reported six import-order and formatting
  differences after paths changed.
- Diagnosis: Imports were updated for ownership first, leaving technically
  valid but non-canonical ordering.
- Resolution: Applied the repository's Biome formatter and reran the clean
  check.
- Remaining caveat: None.

# Heatmap

## Hot

### H1 - Keep Channel Composition Explicit

- Decision: Source is organized by channel without a runtime registry.
- Where: `coordinator/client/src/app/App.jsx` and
  `coordinator/client/src/channels/`.
- Why: Direct composition makes each view discoverable while preserving the
  accepted fixed-channel architecture and its simple control flow.
- Alternatives: A router, channel registry, plugin loader, or the previous flat
  source directory.

## Warm

- Where: `coordinator/client/src/app/`, `voice/`, `diagnostics/`, and `shared/`.
- What: Existing cross-channel behavior moved to directories named after its
  current responsibility.

## Cold

| Where | What |
|---|---|
| `coordinator/client/index.html` | Point the browser at the moved React entry point. |
| `coordinator/client/package.json` | Use recursive built-in test discovery. |
| `endpoint/imac/README.md` | Update the live endpoint-control source path. |

## Stylistic

### S1 - Name Directories After Product Concepts

- Choice: Use `app`, `channels`, `voice`, `diagnostics`, and `shared`; within
  `channels`, use the user-visible channel name.
- Alternative: Group files by technical type in `components`, `utils`, or
  `styles` directories.
- When to apply: Put new code beside the product concept that owns it. Use
  `shared` only after more than one concept consumes the code.
