# SHL-001: Separate The Channel Shell

Previous identifier: `GH-013`.

# What

- Split Today and Music presentation out of `App.jsx` into explicit channel
  components without changing their accepted markup, classes, copy, or
  attribution.
- Renamed the shared Music-named reducer, playback projection, formatting,
  scene cycling, and keyboard classification module to `room-state.js`.
- Moved connection, lighting, channel-toast, identify, and scene presentation
  into one shared room-feedback component rendered above either channel.
- Kept the endpoint connection, identify sound, request lifecycle, keyboard
  listener, and one hard-coded Today/Music choice in `App.jsx`.
- Added focused server-rendered component tests without adding a dependency,
  router, registry, configuration layer, or service change.

# Implementation Walkthrough

## 1. Own Shared Room State By Its Actual Scope

`coordinator/client/src/room-state.js` replaces the Music-specific
`music.js` name. It owns the initial state and reducer for connection, channel,
Today, playback, lighting, and interaction snapshots. It also keeps the
playback position projection, time formatting, safe HTTPS artwork selection,
scene cycling, fixed action identifiers, and keyboard classification used by
the shell.

`coordinator/client/src/room-state.test.js` is the renamed original test file.
Its 11 assertions remain intact, including state independence, terminal
playback, projected progress, artwork validation, formatting, channel
shortcuts, scene cycling, and ignored modifiers and repeats.

## 2. Give Each Channel One Explicit Component

`coordinator/client/src/TodayChannel.jsx` owns the local one-second clock,
timezone formatting, available and unavailable weather presentation,
three-day forecast, and MET Norway attribution.

`coordinator/client/src/MusicChannel.jsx` owns the choice between loaded and
empty Music presentation. Its private components retain artwork loading and
fallback, paused and playing labels, track and episode labels, one-second
progress projection, stopped, unavailable, connecting, and initial loading
states.

`coordinator/client/src/channels.test.js` uses Vite's existing server-side
module loader and React's existing static renderer. It checks available Today,
loaded Music with artwork fallback, stopped and unavailable Music, and the
independence of shared feedback. No test or runtime dependency was added.

## 3. Keep Shared Feedback Above Either Channel

`coordinator/client/src/RoomFeedback.jsx` owns the connection notice, lighting
badge, channel toast, identify overlay, scene overlay, their accepted live
regions, and the action-specific copy used by those presentations.
`RoomFeedback` renders the four feedback surfaces once, after the selected
channel, preserving their DOM order and z-index layering. It imports the exact
shared action identifiers rather than defining a presentation configuration.

## 4. Keep The Shell Concrete

`coordinator/client/src/App.jsx` still opens the single `/api/events`
connection, validates the production client entry, stores endpoint identity,
submits channel and scene actions, reports identify status, generates and plays
the room signal, serializes visible actions, and installs the one keyboard
listener.

The active presentation remains one hard-coded choice:

```jsx
{channel === "today" ? (
  <TodayChannel summary={room.today} />
) : (
  <MusicChannel playback={room.playback} connection={room.connection} />
)}
```

There is no route, registry, manifest, dynamic import, channel configuration,
context provider, or store library.

## 5. Build, Run, And Deploy

Install the exact locked frontend dependencies and run the client locally:

```sh
pnpm --dir coordinator/client install --frozen-lockfile
pnpm --dir coordinator/client dev
```

Vite listens on `127.0.0.1` by default. The client expects the unchanged
coordinator endpoints under `/api`, so full live behavior should be reviewed
through the normal coordinator or deployed service rather than as an isolated
static page.

Build and deploy through the unchanged operator entry point:

```sh
./coordinator/install homelab
```

The installer builds `coordinator/client`, copies the generated client and
coordinator service to the server, and restarts `cortex-home.service`. GH-013
adds no configuration path, credential, migration, or service unit change.

# Problems Encountered

## 1. The Initial Frontend Check Found A Formatting Difference

- Symptom: `pnpm --dir coordinator/client check` rejected the multiline
  `room-state` import in `App.jsx`.
- Diagnosis: The code was valid but did not match Biome's accepted single-line
  formatting for that import length.
- Resolution: Applied the formatter's exact layout and reran Biome, component
  tests, state tests, and the production build successfully.
- Remaining caveat: None.

## 2. The Worktree Had No Installed Frontend Dependencies

- Symptom: The first command reported that the local package existed while
  `node_modules` was missing.
- Diagnosis: This issue worktree had the committed lockfile but had not yet
  installed its worktree-local packages.
- Resolution: Ran
  `pnpm --dir coordinator/client install --frozen-lockfile`; pnpm reused the
  locked packages without changing the manifest or lockfile.
- Remaining caveat: Dependencies remain worktree-local build inputs and are
  not committed.
