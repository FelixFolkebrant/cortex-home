# Implementation Walkthrough

## 1. Run One Locked Text Turn

`coordinator/agent/answer-child.js` validates one JSON line containing only the
request ID, bounded transcript, and normalized context. It creates a fresh Pi
`Agent` with no messages or tools, locks the model to
`google/gemini-3.5-flash-lite`, and rewrites every provider payload with:

```json
{
  "allow_fallbacks": false,
  "data_collection": "deny",
  "only": ["google-vertex/global"],
  "require_parameters": true,
  "zdr": true
}
```

It also sends `store: false`, bounds output to 128 tokens and 1,000 characters,
rejects reasoning, tool calls, truncation, malformed answers, and provider
details, then exits. `coordinator/agent/package.json` and `pnpm-lock.yaml` pin
both Pi packages to `0.82.1`.

`coordinator/agent_runtime.py` starts the fixed child in a new process group
with only `LANG`, `OPENROUTER_API_KEY`, and an optional CA path. It bounds
standard output, rejects any standard error, validates the exact response, and
terminates the group on cancellation or the 20-second model timeout.

## 2. Own Speech And Interaction State In The Coordinator

`coordinator/cortex_home.py` accepts:

```text
POST   /api/agent/interactions/<request-id>
DELETE /api/agent/interactions/<request-id>
POST   /api/agent/interactions/<request-id>/status
```

The upload must be the existing maximum-15-second WAV and carry the current SSE
endpoint token. One `AgentInteraction` owns transcription, a context snapshot,
the child, synthesis, browser playback status, cancellation, and its terminal
phase. Regular room actions share the same busy boundary. Endpoint replacement
or disconnect cancels only its owned interaction, and the coordinator discards
all late work.

`coordinator/speech.py` loads only the selected `VoskRecognizer` and
`PocketTtsSynthesizer`. Text and audio remain in memory. SSE sends only
`requestId` and `phase`; the synthesized WAV returns directly to the owning
HTTP request.

## 3. Play And Cancel Only Current Browser Audio

`coordinator/client/src/agent-interaction.js` uploads the captured WAV, requires
an `audio/wav` response, creates one object URL, plays it, and reports
`speaking` followed by `completed`. Failure reports `failed`. Cancellation
aborts the upload/status request, pauses audio, removes its source, revokes the
URL, and sends the matching `DELETE`.

`App.jsx` keeps the capture ID active through transcription, thinking,
synthesis, and playback. A later exact voice press waits for cancellation
before starting a new capture. Blur, reconnection, another accepted room
action, component cleanup, and content-free terminal SSE events release the
same ownership.

`RoomFeedback.jsx` uses the existing compact microphone bar for
`transcribing`, `thinking`, `speaking`, `completed`, and `failed`, including
Music fullscreen. It never renders a transcript or answer.

## 4. Reconstruct And Deploy The Runtime

Install the locked repository dependencies and run local checks:

```sh
pnpm --dir coordinator/agent install --frozen-lockfile
pnpm --dir coordinator/client install --frozen-lockfile
python3 -m unittest discover -s coordinator/tests
python3 -m unittest discover -s endpoint/imac/tests
pnpm --dir coordinator/agent test
pnpm --dir coordinator/client check
pnpm --dir coordinator/client test
pnpm --dir coordinator/client build
```

Deploy from an interactive terminal:

```sh
./coordinator/install <server-ssh-host>
```

On the first run, enter the dedicated OpenRouter key at the non-echoing prompt.
`coordinator/install` builds the client and stages only the agent source and
lock files. `coordinator/install-host` then:

- downloads official Node `24.18.0` for Linux x86-64 and verifies SHA-256
  `55aa7153f9d88f28d765fcdad5ae6945b5c0f98a36881703817e4c450fa76742`;
- installs the locked production Pi dependency graph under
  `/opt/cortex-home/agent`;
- creates `/opt/cortex-home/venv` with `aiohue==4.8.1`,
  `vosk==0.3.45`, and `pocket-tts==2.1.0`;
- verifies and expands `vosk-model-small-en-us-0.15`, downloads the Pocket TTS
  model and `alba` state under `/opt/cortex-home/models`, and makes artifacts
  root-owned and read-only to the service;
- preserves `/etc/cortex-home/agent.env`, validates its exact syntax,
  ownership, and mode without printing it;
- loads the selected speech engines and validates runtime paths before
  restarting `cortex-home.service`.

`coordinator/files/cortex-home.service` supplies the fixed Pocket cache and
protected environment file. `cortex_home.py` loads the key, Node child, Vosk
model, Pocket model, and `alba` state before constructing the HTTP server, so a
missing requirement prevents port 8080 from opening.

# Problems Encountered

## 1. Cancellation Could Overtake Upload Registration

- Symptom: A rapid replacement could send `DELETE` before the corresponding
  `POST` had registered its interaction.
- Diagnosis: Aborting browser fetch does not prove that the server never
  receives the already-started body.
- Resolution: Unknown valid interaction cancellation now reserves the request
  ID as an endpoint-owned failed tombstone. A late upload is rejected as a
  duplicate.
- Remaining caveat: Tombstones are in-memory and bounded like all coordinator
  request records; a coordinator restart deliberately clears them.

## 2. Local Systemd Verification Cannot See Deployed Paths

- Symptom: `systemd-analyze verify coordinator/files/cortex-home.service`
  reports that `/opt/cortex-home/venv/bin/python` does not exist.
- Diagnosis: The local development machine does not contain the target
  installation tree.
- Resolution: Shell parsing passes, installer tests assert the unit's fixed
  paths, and the target installer imports the installed application, loads the
  full runtime, restarts the service, and requires it to become active.
- Remaining caveat: Run `systemd-analyze verify` against the installed unit on
  the server during manual confirmation.

## 3. Private Provider And Room Evidence Is Not Available Locally

- Symptom: Automated work cannot measure real question quality, provider cost,
  room latency, or audible Sonos output without the private key and appliances.
- Diagnosis: Those checks necessarily cross the accepted private provider and
  physical-room boundaries.
- Resolution: Provider behavior is isolated behind faux Pi and speech
  collaborators, and the exact private deployed pass remains reviewer-owned
  below.
- Remaining caveat: Do not accept the model pin for room use until every
  unchecked qualification item passes.

## 4. Node 24 Corepack Selected The Wrong pnpm Version

- Symptom: A clean Node `24.18.0` rehearsal refused the locked agent install
  because bundled Corepack initially selected pnpm 11 instead of `10.18.2`.
- Diagnosis: Invoking `corepack pnpm` directly did not activate the
  repository's package-manager version before pnpm enforced its own project
  version check.
- Resolution: The installer first activates `pnpm@10.18.2` in its private
  temporary Corepack home, then performs the frozen production install.
- Remaining caveat: None; the corrected clean-room rehearsal passes with the
  official archive.

## 5. Shutdown Initially Relied On A Daemon Request Thread

- Symptom: Coordinator shutdown set the interaction cancellation event, but a
  fast parent exit could finish before the daemon HTTP thread observed it.
- Diagnosis: The supervisor did not retain a closeable handle outside the
  synchronous `answer()` call.
- Resolution: `NodeAgent` now owns the current process handle and its `close()`
  method synchronously terminates the process group. `Coordinator.close()`
  invokes it after marking the interaction failed.
- Remaining caveat: None; the shutdown test proves termination and refuses
  later child starts.

## 6. Corepack Initially Required An Ambient Node Command

- Symptom: The target installer verified and expanded Node `24.18.0`, then
  `/usr/bin/env` reported that `node` was missing when Corepack started.
- Diagnosis: Corepack's launcher resolves `node` through `PATH`. The initial
  clean-room rehearsal accidentally inherited a development-machine Node,
  while the production host correctly had no system Node installation.
- Resolution: Both Corepack commands now receive a fixed `PATH` beginning with
  `/opt/cortex-home/node/bin`. A rehearsal with the ambient environment removed
  proves the downloaded binary alone installs the locked production graph.
- Remaining caveat: None. The partially completed deployment already stored the
  protected key and can be rerun normally.

## 7. Chromium Rejected An Unbound Native Fetch

- Symptom: Releasing the first deployed capture showed `Failed to execute fetch
  on Window, illegal request`, and the coordinator received no interaction.
- Diagnosis: `SpokenInteraction` stored native `window.fetch` directly and then
  called it as an instance method. Chromium requires the native function's
  receiver to remain `Window`; Node's test implementation did not enforce that
  browser rule.
- Resolution: The default dependency is now a lexical wrapper that invokes
  `globalThis.fetch` with its correct receiver. A regression test replaces the
  global function and asserts the observed receiver.
- Remaining caveat: None; redeployment changes the hashed client entry, so the
  connected kiosk reloads the corrected bundle.

# Heatmap

Reference: `../project/HEATMAP.md`.

## Hot

### H1 - One Request Owns The Cancellable Lifecycle

- Decision: One endpoint token and capture request ID own every stage through
  browser playback and terminal state.
- Where: `cortex_home.py`, `agent_runtime.py`, `App.jsx`, and
  `agent-interaction.js`.
- Why: Replacement and disconnect must stop stale private work and audio across
  the browser, coordinator, and child process boundary.
- Alternatives: IDs per stage, browser orchestration, overlapping turns, or a
  persistent child session.

### H2 - Keep The Hosted Boundary Narrow And Fail-Closed

- Decision: Send only bounded transcript plus fresh normalized context to one
  model and one ZDR provider route, without tools, fallbacks, logging, retries,
  or reasoning output.
- Where: `coordinator/agent/answer-child.js`.
- Why: A contextual spoken answer does not need raw audio, credentials,
  provider objects, history, or action authority.
- Alternatives: Direct browser calls, dynamic model routing, broad context,
  tool use, or fallback providers.

### H3 - Process Lifetime Is The Retention Boundary

- Decision: Spawn and supervise one Node process group for every accepted turn.
- Where: `coordinator/agent_runtime.py`.
- Why: Exit makes no-history behavior, cancellation, timeout, and cleanup
  explicit without a reset or multiplexing protocol.
- Alternatives: A persistent process, worker pool, second LAN service, or
  in-process provider integration.
