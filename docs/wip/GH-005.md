# GH-005: Provision The Spotify Receiver

## What

- Added a focused Raspotify provisioning command and included the same receiver
  installation in the complete iMac provisioning path.
- Pinned and validated Raspotify `0.48.2` with librespot `0.8.0` before
  installation.
- Ran the receiver as the existing unprivileged endpoint user through its
  PulseAudio session so Spotify and Chromium share the qualified Sonos route.
- Deployed one `Cortex Home` Spotify Connect receiver and confirmed iPhone
  selection and Spotify playback through the Sonos.

## Acceptance Criteria

- [x] The main iMac provisioning path installs the reviewed `amd64` Raspotify
  package only after its package name, version, architecture, dependency, and
  checksum pass.
- [ ] Provisioning is fail-fast and rerunnable without committing credentials
  or host identity.
- [x] Raspotify runs as the unprivileged `cortex-endpoint` user and sends audio

- [x] Spotify on the iPhone discovers exactly one receiver named `Cortex Home`.

- [x] A playback sample of no more than 60 seconds records CPU, memory, and

- [x] Repository shell, systemd, and whitespace checks pass.
- [x] This record contains exact automated and reviewer-owned manual
  confirmation steps.

## Plan Diff

- Added a focused `provision-raspotify` command so deploying this capability
  does not require re-entering the base endpoint's Wi-Fi and coordinator
  settings.
- The first install exposed missing destination-directory creation and an
  interactive package conffile prompt. The user created the directories to
  finish the live install; provisioning now uses `install -D` and explicitly
  retains the reviewed configuration during package installation.
- The first Spotify attempt selected a station/autoplay context that librespot
  could not resolve. Selecting an ordinary track completed playback without an
  audio-backend error.
- The saved Master and Headphone mixer controls each remain at 70%, represented
  by ALSA as -19 dB. Playback works but is quiet; gain tuning was left outside
  this receiver-installation issue at the user's direction.
- At the user's direction, the remaining provisioning rerun, concurrent
  identify, restart-recovery, and gain judgments do not block GH-005 closure.
  They remain unchecked so this record does not invent manual confirmation.

## Hot

### H1 - Share The Endpoint PulseAudio Session

- Decision: Run the packaged librespot receiver as `cortex-endpoint` through
  that user's PulseAudio server.
- Where: `endpoint/imac/files/raspotify.service.conf` and
  `endpoint/imac/files/cortex-raspotify`.
- Why: Chromium already owns this sound-server route. Sharing it avoids direct
  ALSA contention and does not add a system audio server.
- Alternatives: Direct ALSA; a system PulseAudio daemon; network audio from the
  ThinkPad.

### H2 - Fail When The Reviewed Package Changes

- Decision: Pin the accepted package metadata and checksum while downloading
  through the upstream architecture-specific URL.
- Where: `endpoint/imac/provision-raspotify-host`.
- Why: A changing `latest` package must not silently alter dependencies,
  service hardening, or receiver behavior during endpoint reprovisioning.
- Alternatives: Trust the latest package; add the upstream apt repository;
  build librespot locally.

## Notes

- Raspotify and its bundled librespot implementation remain unofficial,
  Premium-only software intended for personal use.
- A provider context failure is distinct from an audio-route failure: the
  unsuccessful station attempt never opened the PulseAudio sink, while a
  normal track immediately used the running analog PCM.
- Gain currently crosses Spotify soft volume, PulseAudio, two saved iMac mixer
  controls, Sonos line-in source level, and Sonos room volume. Later tuning
  should keep the iMac close to line level and use the controller or Sonos for
  normal listening changes.
- Planpoint 2 now accepts normalized local librespot events as the playback
  source. GH-006 can begin without a Spotify developer application, Web API
  polling, or another architecture decision.
