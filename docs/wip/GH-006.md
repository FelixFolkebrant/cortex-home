# GH-006: Publish Spotify Playback State

## What

- Added a repository-owned iMac adapter that combines supported librespot
  events into one normalized, runtime-only playback observation.
- Added a bounded coordinator observation route that validates exact playback
  fields, assigns a UTC observation timestamp, and retains only the latest
  snapshot in memory.
- Published changed `music.playback` snapshots through the existing server-sent
  event connection and sent the current snapshot to every new endpoint
  connection.
- Wired service-stop reporting so receiver failure replaces stale playing state
  without making audio depend on successful reporting.

## Plan Diff

- The adapter keeps its partial event state in Raspotify's systemd-managed
  `/run/raspotify` directory. This state is erased at boot and contains only the
  normalized observation needed to combine `track_changed` metadata with later
  position events.
- The systemd drop-in also invokes the adapter from `ExecStopPost`. Librespot
  does not emit a playback event when its process is killed, so this is the
  smallest path that replaces a stale playing snapshot after service failure.
  The command is prefixed with `-` so reporting cannot change Raspotify's
  service outcome or restart behavior.

## Implementation Walkthrough

### 1. Normalize Receiver Events

`endpoint/imac/files/cortex_playback_event.py` reads only the librespot fields
needed for the active event. A `track_changed` event supplies the loaded track
or episode metadata; later `playing`, `paused`, `seeked`, and
`position_correction` events replace its status and position. `stopped`,
`end_of_track`, `unavailable`, and `session_disconnected` replace the loaded
item with a terminal snapshot.

The adapter stores the current normalized observation at:

```text
/run/raspotify/cortex-playback.json
```

The Raspotify unit creates and owns that runtime directory. The state is
atomically replaced, contains no provider account or client fields, and is not
durable across boot.

`endpoint/imac/files/raspotify.conf` sets the repository-installed adapter as
`LIBRESPOT_ONEVENT`. `endpoint/imac/files/raspotify.service.conf` reports
`unavailable` after the receiver exits. `endpoint/imac/provision-raspotify-host`
installs both fixed files and the adapter.

Restore or deploy the receiver snapshot with:

```sh
./endpoint/imac/provision-raspotify
```

### 2. Validate And Own Playback State

`coordinator/cortex_home.py` accepts observations at:

```text
POST /api/observations/music/playback
```

The route continues to use the accepted LAN-only coordinator boundary. It
accepts an exact three-field object and validates status, nullability, Spotify
URI and item-type agreement, string and collection bounds, HTTPS artwork,
duration, and position. Boolean values are not accepted as integers. A
malformed observation returns `invalid_playback` and cannot replace the prior
valid state.

After validation, the coordinator assigns `observedAt` as an ISO 8601 UTC
timestamp, replaces its single in-memory snapshot, and publishes a
`music.playback` event when the state changed. It begins with `unavailable` and
sends the current snapshot immediately after each endpoint connection's
`ready` event.

Deploy the coordinator before the receiver:

```sh
./coordinator/install <server-ssh-host>
./endpoint/imac/provision-raspotify
```

The first command asks for the configured ThinkPad SSH destination at runtime;
the second uses the existing `imac` SSH destination. Neither destination is
committed.

### 3. Recover Reporting

The adapter writes the normalized runtime state before making its two-second
HTTP request. If the coordinator or network is unavailable, it prints only
`Playback reporting failed.` and exits nonzero. Librespot records the failed
hook without stopping playback. The next supported event loads the saved state
and retries.

Stopping or killing Raspotify invokes the same adapter with a fixed
`unavailable` event. A restarted coordinator begins unavailable, and a
restarted receiver emits fresh metadata before its next playback state. No
login, provider credential, database, or manual state repair is involved.

## Problems Encountered

### 1. Librespot Splits Metadata And Position Across Events

- Symptom: Play, pause, and seek events contain an item ID and position but not
  the title, creators, collection, artwork, or duration required by the
  normalized snapshot.
- Diagnosis: In the pinned librespot 0.8.0 source, complete metadata appears on
  `track_changed`; position-bearing events intentionally carry only their
  changing fields.
- Resolution: The adapter atomically retains one normalized partial snapshot in
  Raspotify's runtime directory and merges later supported events into it.
- Remaining caveat: Installing the adapter during an already active track may
  report unavailable until librespot emits the next metadata event.

### 2. Process Failure Does Not Emit A Librespot Event

- Symptom: A killed receiver could leave the coordinator's last snapshot as
  playing.
- Diagnosis: `--onevent` covers player events, not process termination.
- Resolution: The Raspotify drop-in invokes the adapter with a fixed
  `unavailable` state from `ExecStopPost`.
- Remaining caveat: If the coordinator is unreachable at the same moment, the
  report cannot arrive. A coordinator restart begins unavailable, and the next
  receiver event retries from runtime state.

## Heatmap

Reference: `../project/HEATMAP.md`.

## Hot

### H1 - Normalize Before The Client Boundary

- Decision: Keep librespot event names and environment variables inside the
  iMac adapter and send only complete normalized observations.
- Where: `endpoint/imac/files/cortex_playback_event.py`
- Why: The coordinator and later Music channel do not need provider event
  ordering, account fields, client identity, or host metadata.
- Alternatives: Forward raw events; reduce them in React; poll Spotify's Web
  API.

### H2 - Keep Playback State Ephemeral

- Decision: Retain one runtime adapter state and one in-memory coordinator
  snapshot, with no history or cross-restart durability.
- Where: `/run/raspotify/cortex-playback.json` and
  `coordinator/cortex_home.py`
- Why: Track metadata and position arrive in separate events, but now-playing
  needs only the latest accepted state. Fresh events recover both processes.
- Alternatives: Add a database; append an event log; make the browser
  authoritative.

### H3 - Accept Observations At The Existing LAN Boundary

- Decision: Add no credential exchange for the bounded, read-only observation
  route.
- Where: `coordinator/cortex_home.py`
- Why: It exposes no action or durable data and uses the same LAN-scoped HTTP
  service as `endpoint.identify`.
- Alternatives: Provision a shared secret; add another interface; tunnel
  reports through the browser connection.

## Warm

## Notes

- The adapter selects the first artwork URL from librespot's ordered cover list
  and does not download, proxy, cache, or render it.
- Episode creator and collection use librespot's show name because the local
  event contract exposes no separate episode publisher field.
- The `music.playback` event is intentionally ignored by the GH-004 screen;
  GH-007 will render the accepted snapshot after this live path is qualified.
