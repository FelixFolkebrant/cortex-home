# Implementation Walkthrough

## 1. Preserve The Observed Endpoint Baseline

The repository-owned session entry point is
`endpoint/imac/files/cortex-endpoint-session`. The live endpoint matches it:

| Boundary | Observed baseline |
|---|---|
| Operating system | Ubuntu 24.04.4 LTS, x86-64 |
| Display session | LightDM, X11 display `:0`, Openbox, 1920×1200 |
| Kiosk | Snap Chromium 150 in the session script's restart loop |
| Composition | No Picom, Compton, or xcompmgr process |
| Graphics | Kernel `radeon` driver on a Radeon HD 2600-class adapter |
| Memory | 4 GB |
| Discovery | Avahi active and listening for mDNS |
| Audio | Endpoint PulseAudio session active; repository policy selects the one built-in PCI analog sink |
| Receiver | UxPlay absent; Ubuntu candidate `1.68.2-1build2` |

The Chromium process is launched again two seconds after it exits. Closing its
window is therefore not a stable way to control the experiment. Openbox owns
the recovery-terminal and endpoint-volume chords, while the channel shortcuts
remain browser key handlers and need Chromium focus.

## 2. Use The Distribution Package For The Experiment

Ubuntu 24.04 offers UxPlay `1.68.2-1build2`. The package uses the same X11,
Avahi, GStreamer, OpenSSL, and libplist boundaries documented by upstream and
supports optional PIN pairing, fullscreen X11 output, an explicit PulseAudio
sink, and explicit video dimensions.

Upstream currently offers UxPlay 1.73.6. Building that release would require a
C/C++ toolchain, `pkg-config`, CMake 3.10 or newer, and the development
packages for OpenSSL, libplist, Avahi DNS-SD, GStreamer base, and optionally
X11. Those development packages are not installed on the endpoint and are not
needed to answer GH-019, so the experiment does not build from source.

Two temporary no-root probes were attempted before choosing the normal package:

1. UxPlay plus its DNS-SD compatibility library had no unresolved linked
   libraries and printed its help, but startup failed because the endpoint has
   no usable GStreamer base, good, bad, or libav plugin set.
2. A 75 MiB tree extracted from the simulated new package set still failed
   plugin discovery when libav reached a library outside the extracted runtime
   closure.

Both trees used dedicated paths below `/tmp`, advertised no receiver, and were
deleted by an exit trap. A custom package resolver would add experiment-only
machinery and is not pursued.

## 3. Install And Record Only The Physical Test Inputs

On the iMac, press `Control`+`Option`+`Return`, enter the administrator account,
and snapshot the installed package set before changing it:

```sh
su - imac
dpkg-query -W -f='${db:Status-Abbrev} ${binary:Package}\n' |
  awk '$1 == "ii" { print $2 }' |
  sort > /tmp/cortex-gh019-packages-before
sudo apt install --no-install-recommends uxplay wmctrl
dpkg-query -W -f='${db:Status-Abbrev} ${binary:Package}\n' |
  awk '$1 == "ii" { print $2 }' |
  sort |
  comm -13 /tmp/cortex-gh019-packages-before - \
    > /tmp/cortex-gh019-packages-added
uxplay -h | sed -n '1,3p'
cat /tmp/cortex-gh019-packages-added
exit
```

Record the reported UxPlay version and added package names in this issue, but
do not copy the endpoint hostname, addresses, device identifiers, PIN, client
name, or raw logs.

Start UxPlay from the recovery terminal as the graphical
`cortex-endpoint` user so it shares the existing X11 and PulseAudio session:

```sh
test ! -e /tmp/cortex-gh019-uxplay-home
mkdir -m 700 /tmp/cortex-gh019-uxplay-home
HOME=/tmp/cortex-gh019-uxplay-home \
  uxplay \
  -n 'Cortex AirPlay Experiment' \
  -nh \
  -pin \
  -fs \
  -s 1920x1200 \
  -as pulsesink
```

Do not redirect UxPlay output to a file. Keep the recovery terminal visible
only long enough to read the random PIN and content-free failures. Use
`Control`+`C` in that terminal to stop the receiver.

## 4. Exercise Receiver And Window Recovery

With UxPlay running:

1. Open iPhone Control Center, select Screen Mirroring, select
   `Cortex AirPlay Experiment`, and enter the terminal PIN.
2. Record whether discovery, pairing, first moving image, stop, and reconnect
   succeed. Record only behavior and elapsed time, never mirrored content.
3. Observe whether the receiver is fullscreen and borderless and whether it
   initially opens above Chromium.
4. Press the existing channel and recovery-terminal shortcuts. Record which
   actions still work with UxPlay focused and whether focus can return to
   Chromium without terminating the mirror.
5. In a second recovery terminal, run `wmctrl -l -x` to identify the UxPlay and
   Chromium windows. Lower the receiver beneath Chromium with:

   ```sh
   wmctrl -r '<observed UxPlay window title>' -b add,below
   ```

6. Confirm the opaque Chromium baseline completely hides the lower receiver
   and that Today, Music, Camera, shared room feedback, and their normal
   keyboard behavior still work.

The lower-window title is deliberately observed at runtime rather than assumed
or stored as endpoint configuration.

## 5. Keep Measurements Content-Free And Bounded

Before mirroring and while it is active, run these from a recovery terminal.
Each sampling window is ten seconds:

```sh
pactl get-default-sink
pactl list short sink-inputs
uxplay_pid=$(pgrep -n uxplay)
timeout 10 top -b -d 1 -p "$uxplay_pid"
```

Record the default sink name only as “the built-in PCI analog sink,” whether a
UxPlay sink input appears there, approximate UxPlay CPU and resident memory,
visible frame drops or tearing, and whether the Sonos line-in plays mirror
audio. Do not record audio, screen content, sink-input metadata, addresses, or
device identity. Stop each diagnostic immediately if it exceeds 60 seconds.

## 6. Restore The Kiosk After Every Physical Run

First stop UxPlay with `Control`+`C`. Remove its temporary HOME as the endpoint
user, then remove exactly the packages that were absent before the experiment:

```sh
rm -rf -- /tmp/cortex-gh019-uxplay-home
su - imac
xargs -r sudo apt purge -- < /tmp/cortex-gh019-packages-added
rm /tmp/cortex-gh019-packages-before
rm /tmp/cortex-gh019-packages-added
exit
/usr/local/bin/cortex-endpoint-audio-route >/dev/null
pgrep -a openbox
pgrep -a chrome | sed -n '1p'
```

The final two commands must show Openbox and the Chromium kiosk. Confirm Today,
Music, Camera, shared feedback, and the endpoint volume shortcuts behave as
they did before the run. No UxPlay process, package, temporary HOME, service,
autostart entry, compositor, or changed audio route may remain.

# Problems Encountered

## 1. A minimal unpacked UxPlay binary could not start

- Symptom: A five-second headless startup stopped before advertisement and
  reported missing GStreamer `app`, `libav`, `playback`, `autodetect`, and
  `videoparsersbad` plugins.
- Diagnosis: Package records for some GStreamer plugin sets remain on the
  endpoint, but the corresponding runtime plugins are not installed.
- Resolution: Use Ubuntu's dependency-resolved package for the physical
  experiment and record every newly installed package for exact cleanup.
- Remaining caveat: The package install and physical receiver test still
  require administrator authentication and an iPhone.

## 2. Extracting the simulated new package set was not self-contained

- Symptom: A 75 MiB, 42-package temporary runtime tree still stopped before
  advertisement; its libav plugin first failed on missing `libblas.so.3`.
- Diagnosis: GStreamer plugins dynamically load a broader runtime closure than
  the simple simulated-new-package extraction captured.
- Resolution: Deleted the temporary tree and rejected a custom recursive
  package-bundling mechanism as unnecessary issue-only infrastructure.
- Remaining caveat: None; no package or endpoint configuration was changed.

## Hot

### H1 - Prefer A Reproducible Distro Package To A Custom Runtime Bundle

- Decision: Use Ubuntu's UxPlay 1.68.2 package for the bounded physical test
  and capture the exact newly installed package set for teardown.
- Where: Physical experiment commands in this record.
- Why: The unpacked binary and simulated package tree both failed GStreamer
  plugin discovery, while building upstream or resolving a private runtime
  closure would add machinery unrelated to the composition decision.
- Alternatives: Build upstream 1.73.6, create a recursive unpacked bundle, or
  defer the receiver test.
- Review focus: A discovery, pairing, or decoder failure in Ubuntu's older
  package is not evidence against UxPlay 1.73.6. Test the current upstream
  release as a bounded fallback before recommending deferral when version skew
  could explain the failure.

### H2 - Stop At The Opaque Stack Until Native Layering Is Proven

- Decision: Test UxPlay below unchanged opaque Chromium before creating any
  transparent/translucent browser experiment.
- Where: Physical window-stack sequence in this record.
- Why: The endpoint has no desktop compositor, so transparency is not a
  credible product boundary unless the native z-order and Chromium focus model
  work first.
- Alternatives: Add a compositor, hide Chromium, or immediately modify the
  client.
