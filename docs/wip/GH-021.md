# GH-021: Wake The Room

# What

- Added the coordinator-owned, one-shot alarm schedule and its normalized SSE
  snapshot.
- Added fixed arm, disarm, and dismiss actions; atomic alarm persistence; and
  Europe/Stockholm next-occurrence and restart-recovery behavior.
- Added the fifth fixed Alarm channel, its keyboard-only time editor, and the
  observed-arm `Ctrl`+`Enter` sleep interaction.
- Added five-minute minute adjustments with a held-`Alt` one-minute override;
  arrow keys repeat while held.
- Sleep requests retry the endpoint bridge's bounded listener gap and preserve
  the endpoint's diagnostic reason when a request fails.
- RTC sleep uses suspend-to-idle, avoiding the iMac8,1 Radeon corruption
  observed after deep suspend while retaining timed wake.
- Alarm audio now stops when the alarm is dismissed or disarmed, even if the
  Alarm view immediately changes. The disarmed view also exposes an `A`-opened,
  arrow-key sound selector backed by an iMac folder writable over `scp`.

# Plan Diff

- The accepted plan was updated before implementation: plain Enter arms the
  alarm, and the later sleep command is `Ctrl`+`Enter` after observed arming.
- The final editor refinement reverses the arrow direction, allows held arrow
  repeats, uses five-minute minute steps, and uses Alt+Up/Down for one-minute
  minute steps.
- Physical qualification changed the power mode from deep suspend-to-RAM to
  suspend-to-idle because the legacy Radeon display resumes from S3 with
  corrupted panel state.
- Alarm audio expanded from one replaceable fixed file to a bounded
  endpoint-local catalog and keyboard selector.

# Implementation Walkthrough

1. `coordinator/alarm.py` owns the fixed snapshot schema, local-time
   calculation, DST validation, due-or-missed recovery decision, and atomic
   JSON replacement.
2. `coordinator/cortex_home.py` adds `alarm.arm`, `alarm.disarm`, and
   `alarm.dismiss` to `/api/actions`, publishes `alarm.state` on endpoint
   connection and state changes, and schedules the one in-process due timer.
3. `coordinator/files/cortex-home.service` creates the service-owned
   `/var/lib/cortex-home` state directory. `./coordinator/install
   <server-ssh-host>` copies `alarm.py`, installs the unit, and restarts the
   coordinator.
4. `coordinator/client/src/AlarmChannel.jsx` mounts the editor only in the
   Alarm channel. `coordinator/client/src/alarm-editor.js` accepts exact
   editing keys, plain Enter to arm, Escape to disarm, and `Ctrl`+`Enter` only
   for an observed armed snapshot. Up/Down repeat while held; minute steps are
   five minutes, or one minute with Alt held. `Ctrl`+`Alt`+`5` selects the
   channel; selecting it from AirPlay first turns the receiver off.
   When the coordinator publishes `ringing`, that channel replaces the editor
   with a live Europe/Stockholm clock and its one-key dismissal instruction.
5. On the due timer, `coordinator/cortex_home.py` selects Alarm and invokes
   only the exact `Warm low` Hue scene through the existing observed scene
   activator. A scene failure stays visible on the ringing alarm and does not
   prevent dismissal or trigger an automatic retry.
6. `endpoint/imac/files/cortex-endpoint-alarm` owns one looping `mpg123`
   player for the selected regular MP3 in
   `/var/lib/cortex-endpoint/alarm-audio`.
   The origin-bound loopback bridge lists and selects only bounded file names;
   the Alarm view opens that list with `A`, moves with Up/Down, and applies with
   Enter. The ringing-state effect stops the player on dismissal, disarming,
   or view unmount. `scp <local-mp3>
   imac:/var/lib/cortex-endpoint/alarm-audio/` adds new options without a
   rebuild or restart.
7. `Ctrl`+`Enter` sends the observed `firesAt` through `alarm.sleep`. The
   browser sends only its UTC epoch through the shared one-retry endpoint
   control boundary. The bridge stops UxPlay, checks the alarm file, bounds the
   epoch again, and starts the root-owned `cortex-endpoint-rtc-suspend` helper.
   The helper waits two seconds for the browser acknowledgement, then invokes
   only `/usr/sbin/rtcwake --utc --mode freeze --time <epoch>`.
   Suspend-to-idle preserves the legacy Radeon display state that deep S3
   resume corrupts on this iMac.

Deploy or reconstruct the completed slice with:

```sh
./coordinator/install <server-ssh-host>
./endpoint/imac/provision-alarm
./endpoint/imac/provision-alarm-audio <local-mp3>
```

Additional sounds need only:

```sh
scp <local-mp3> imac:/var/lib/cortex-endpoint/alarm-audio/
```

# Problems Encountered

## 1. The deployment installer omitted the new local module

- Symptom: The installer coverage test reported that `alarm.py` was not copied
  into `/opt/cortex-home`.
- Diagnosis: The top-level deployment copy and host installer both use explicit
  module lists.
- Resolution: Added `alarm.py` to both lists.
- Remaining caveat: None.

## 2. Focused endpoint deployment did not accept direct execution

- Symptom: The focused endpoint installer failed because its staged root script
  was not executable; the audio installer could not read an interactive sudo
  password.
- Diagnosis: The staged host script had mode `0644`, and the audio SSH command
  did not allocate a terminal.
- Resolution: Made the host installer executable, added terminal allocation to
  the audio command, and deployed the corrected scripts successfully.
- Remaining caveat: None.

## 3. Sleep could fail before the endpoint suspended

- Symptom: `Ctrl`+`Enter` reported `sleep_failed`; repeating the request could
  then suspend the iMac.
- Diagnosis: The sleep call bypassed the existing retry for the one-connection
  bridge's preflight/listener gap. Once accepted, `rtcwake` could also suspend
  before Chromium acknowledged completion to the coordinator.
- Resolution: Routed sleep through the shared one-retry endpoint control
  boundary and added a two-second acknowledgement window before `rtcwake`.
- Remaining caveat: None; the deployed endpoint accepted the sleep request.

## 4. Radeon display state was corrupted after resume

- Symptom: The resumed panel appeared severely washed out, as if a translucent
  white layer covered the interface.
- Diagnosis: The iMac8,1 uses the legacy Radeon RV630 path, and the kiosk
  reapplied its display mode only at login. The fact that the tint also
  affected terminals and the shutdown console rules out application CSS and
  points to the Radeon encoder or panel state. Live inspection showed normal
  255/255 backlight and 1.0 gamma values. Correctly authorized gamma rewrites,
  mode resets, and a LightDM restart did not change the tint. Historical
  reports reproduce the same early-iMac Radeon corruption only after deep
  suspend on 64-bit EFI.
- Resolution: Changed the bounded RTC helper from deep suspend-to-RAM
  (`--mode mem`) to suspend-to-idle (`--mode freeze`), avoiding the broken S3
  hardware restoration path while retaining timed RTC wake.
- Remaining caveat: Suspend-to-idle saves less power than deep suspend.

## 5. The endpoint could not read the installed alarm file

- Symptom: Sleep failed before suspend, and the interface showed only
  `sleep_failed`.
- Diagnosis: The MP3 was group-readable, but `/home/imac` did not grant the
  `cortex-endpoint` user directory traversal, so the endpoint reported the
  selected alarm file as missing and rejected sleep.
- Resolution: Moved the shared catalog to the traversable service path
  `/var/lib/cortex-endpoint/alarm-audio` and retained `imac` ownership for
  direct file management. Sleep failures now preserve the bounded endpoint
  reason instead of replacing it with `sleep_failed`.
- Remaining caveat: None after reinstalling the MP3 at the new path.
