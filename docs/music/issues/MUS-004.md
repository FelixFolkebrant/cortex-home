Previous identifier: `GH-015`.

# What

- Replaced the normal Music heading strip with one local Spotify mark and
  `Spotify` source label while preserving the accepted player states and
  metadata.
- Reduced stopped Music to the Spotify mark/name and one connection
  instruction: `Choose "Högtalaren" as speaker in Spotify to connect`.

  connection, channel, identify, and scene feedback in normal views.

  creator typography with creators directly below the title.
- Made the current title itself the playback progress indicator: the completed

  uses pure black or white at 60% opacity, selected for the stronger computed
  contrast. Creators use that monochrome color at 40% opacity.
- Added the final-ten-second upcoming-item composition for complete optional
  upcoming metadata, including an upcoming-cover accent and pure black or white
  fallback.
- Retained the last complete track through brief item-less boundary snapshots
  and added a sharp 400ms ease-in-out left swipe for confirmed track changes.
- Faded the surrounding majority color between the previous and current cover
  while keeping the previous resolved color during sampling.
- Kept source, collection, elapsed time, duration, controls, and shared room
  feedback out of fullscreen.
- Repaired coordinator deployment so the existing `context.py` runtime module
  is copied and the installed coordinator import is checked before service
  restart.

  its visual design could be decided separately. The user supplied that design
  during implementation, so the same issue now completes the fullscreen
  composition instead.
- The requested upcoming treatment is implemented for complete optional item

  librespot preloading event exposes only an upcoming Spotify identifier, not

  the same predictable leftward motion.

# Implementation Walkthrough

## 1. Preserve The Normal Player And Name Its Source

`coordinator/client/src/MusicChannel.jsx` keeps the existing loaded, stopped,
unavailable, connecting, first-observation, long-metadata, progress, and
artwork-fallback paths. `SpotifySource` replaces the old Cortex Home,
playback-state, and item-type strip with one local inline SVG mark and source
name in all normal Music states. The stopped presentation intentionally
contains only that source identity and `Choose "Högtalaren" as speaker in
Spotify to connect`.

`coordinator/client/src/RoomFeedback.jsx` accepts `showLightingStatus`.
`coordinator/client/src/App.jsx` passes it only for Today, so the steady Hue
badge belongs to Home while normal transient feedback remains shell-owned.

## 2. Keep Fullscreen Local To Music

`coordinator/client/src/room-state.js` classifies only non-repeating
`Ctrl`+`M` with no Alt, Meta, or Shift modifier while the observed channel is
Music. `coordinator/client/src/App.jsx` owns the boolean presentation state,
changes it without a network request, and resets it on an observed channel
exit.

While active, `App` renders only `MusicFullscreen`; the normal channel
background, player, connection notice, scene status, and interaction overlays
are omitted.

## 3. Derive The Artwork Palette In The Browser

`coordinator/client/src/music-palette.js` reduces a separately loaded
cross-origin artwork image to a 64×64 canvas sample. It groups opaque pixels
into five-bit RGB buckets. The largest bucket becomes the surrounding
background.

The accent calculation considers only recurring buckets, then scores them by
distance from the background, saturation, and presence. This favors a small
but meaningful red detail over common neutral highlights while still allowing
white to win for genuinely monochrome covers. Relative luminance and contrast
ratio choose exact `#000000` or `#ffffff` for the dim text.

If sampling is unavailable or blocked, the visible artwork still loads
normally and the presentation uses its safe dark fallback. Upcoming text uses
the current background's contrast-selected black or white whenever its own
accent is unresolved.

## 4. Make Typography Carry Playback State

`coordinator/client/src/MusicChannel.jsx` reuses the accepted local playback
projection. It converts current position to a percentage and supplies that
percentage to a hard-stop text gradient. The title and creators form an
upper-left-aligned column before the group is rotated `-90deg`, keeping the
creators directly below the title. The completed color moves visibly through
the title from its start as playback advances; the unplayed monochrome segment
is 60% opaque and the creators are 40% opaque.

`coordinator/client/src/styles.css` sizes the cover to
`min(100vw, 100svh)`, centers it, and lets the computed background fill the
remaining sides. It places the current metadata in the left rail and the
smaller upcoming metadata in the right rail. Title size is bounded by both the
viewport and title length without adding another visible element.

When a complete `nextItem` is present, the right treatment stays absent until
`durationMs - positionMs <= 10000`. Its fill progresses from zero to 100
percent over the same final ten seconds. The normalized live receiver does not
currently publish `nextItem`, so the component never invents a title, creator,
or cover.

At a track boundary, `MusicFullscreen` retains the last complete snapshot for
800ms instead of replacing it with an item-less terminal snapshot. Once a
different Spotify URI arrives, the cached artwork and typography leave to the
left while the new composition enters from the right with a sharp 400ms
ease-in-out curve. The client retains a small bounded palette cache so the
surrounding color stays stable while the new cover is sampled, then
`background-color` uses the same 400ms curve to reach the new majority color.
Reduced-motion preference disables both effects.

## 5. Keep Deployment Fail-Loud

`coordinator/install` now includes `context.py` in the staged files.
`coordinator/install-host` installs it at `/opt/cortex-home/context.py` and
runs:

```sh
PYTHONPATH=/opt/cortex-home \
  /opt/cortex-home/venv/bin/python -c "import cortex_home"
```

The import check happens before the systemd service restart.
`coordinator/tests/test_install.py` compares local imports in
`cortex_home.py` with both deployment stages and asserts the installed import
preflight remains present.

## 6. Build, Run, And Deploy

Install locked dependencies, check, test, and build:

```sh
pnpm --dir coordinator/client install --frozen-lockfile
pnpm --dir coordinator/client check
pnpm --dir coordinator/client test
pnpm --dir coordinator/client build
```

Run the client against a local coordinator:

```sh
pnpm --dir coordinator/client dev
```

Deploy the production client and coordinator:

```sh
./coordinator/install homelab
```

No migration, credential, environment variable, endpoint reprovision, or
service configuration change is required.

# Problems Encountered

## 1. The Receiver Cannot Truthfully Populate Upcoming Metadata

- Symptom: The design needs the next title, creator, and cover before the
  current item ends, but the current playback snapshot contains only the
  active item.
- Diagnosis: Librespot's preloading event provides the upcoming Spotify
  identifier but not the complete display metadata. Adding Spotify Web API
  authentication or scraping an unrelated page would expand this issue beyond
  its accepted trust and integration boundary.
- Resolution: Implemented the complete final-ten-second component behavior for
  optional upcoming item input and used the requested contrast-selected black
  or white fallback when the upcoming accent cannot be resolved. The live
  client does not fabricate missing metadata.
- Remaining caveat: A later accepted metadata source is required before
  upcoming title and creator text can appear on the deployed receiver.

## 2. The Initial Execution Environment Blocked Loopback Sockets

- Symptom: Vite preview startup, headless browser capture, the coordinator HTTP
  test class, and four scene-verifier tests failed with `EPERM` while creating
  local sockets.
- Diagnosis: The initial environment prohibited socket creation; the failures
  occurred before application assertions and were unrelated to the fullscreen
  implementation.
- Resolution: Used socket-free checks during implementation, then reran the
  complete coordinator discovery suite in an unrestricted environment. All 71
  coordinator tests passed.
- Remaining caveat: Physical viewport judgments remain manual.

## 3. The Initial Production Audit Could Not Reach The Registry

- Symptom: `pnpm audit --prod` retried and failed DNS lookup with `EAI_AGAIN`.
- Diagnosis: The initial environment could not resolve the package registry.
- Resolution: Confirmed the package manifest and lockfile were unchanged, then
  reran `pnpm --dir coordinator/client audit --prod` with network access. It
  reported no known vulnerabilities.
- Remaining caveat: None.

## 4. Fullscreen Metadata Lost Its Intended Hierarchy

- Symptom: The rotated title and creators occupied one row, so the creators
  appeared before the title in the reading hierarchy. An opaque unplayed title
  segment also made progress disappear when the artwork accent resolved to the
  same black or white.
- Diagnosis: The metadata wrapper used the default flex row and the text
  gradient reused an opaque monochrome color.
- Resolution: Changed the metadata wrapper to an upper-left-aligned column and
  composited the unplayed title segment at 60% opacity and creators at 40%.
- Remaining caveat: None; the user confirmed the corrected hierarchy and
  opacity on the room display.

## 5. Track-Boundary Snapshots Caused A Black Flash

- Symptom: Fullscreen became black between the end of one song and receipt of
  the next song's complete metadata.
- Diagnosis: The client rendered every item-less `stopped` or `unavailable`
  snapshot immediately, discarding the only complete artwork and typography
  available during the boundary.
- Resolution: Retained the last complete snapshot for an 800ms grace period,
  animated confirmed URI changes left, and faded the background only after the
  next palette resolves.
- Remaining caveat: A song that produces a persistent `unavailable` snapshot
  still needs endpoint, coordinator, and artwork diagnostics; the grace period
  deliberately does not hide a lasting receiver failure.
- Field confirmation: A reproduced black screen showed `status: unavailable`
  with `item: null`, confirming that artwork rendering was not the trigger.
  The receiver journal had no entry in the correlated two-minute window; older
  Librespot context warnings are not enough to identify which normalized event
  cleared the item.

`endpoint/imac/README.md` contains the bounded receiver, normalized-state, and
coordinator journal commands needed to diagnose a persistent recurrence
without exposing the event-stream token.

# Heatmap

## Hot

### H1 - Keep Fullscreen As Local Presentation State

- Decision: `Ctrl`+`M` changes only the active Music presentation.
- Where: `coordinator/client/src/App.jsx` and
  `coordinator/client/src/room-state.js`.
- Why: The browser already runs as a kiosk and fullscreen does not represent a
  new room channel or coordinator action.
- Alternatives: Browser Fullscreen API, a new channel, a coordinator action, or
  kiosk changes.

### H2 - Keep Missing Upcoming Metadata Honest

- Decision: Render the upcoming treatment only from complete item data and
  never infer or fabricate title, creator, or cover.
- Where: `coordinator/client/src/MusicChannel.jsx`.
- Why: The accepted receiver contract cannot supply those values before the
  item starts, and adding a new Spotify integration is a separate trust and
  deployment decision.
- Alternatives: Hard-coded demo metadata, title-only oEmbed lookup, page
  scraping, or Spotify Web API authentication.

# Notes

- The visible artwork image and the palette-sampling image are deliberately
  separate. A cross-origin canvas restriction can therefore degrade color
  selection without hiding otherwise displayable artwork.
- The next-item monochrome fallback follows the current background contrast,
  as requested.
- The user confirmed the corrected fullscreen hierarchy, opacity, and track
  transition on the room display. The unchecked manual steps remain explicit
  reviewer judgments for stopped, fallback, and representative viewport and
  cover combinations.
