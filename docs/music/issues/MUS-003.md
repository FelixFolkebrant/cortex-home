# MUS-003: Present The Music Channel

Previous identifier: `GH-007`.

## What

- Replaced the provisional endpoint-ready screen with a full-screen Music view
  driven by the coordinator's initial and subsequent `music.playback`
  snapshots.
- Added a dependency-free room-state model that keeps playback, coordinator
  connection, and temporary identify feedback independent.
- Added bounded local progress projection, loaded and terminal playback
  presentations, direct HTTPS artwork, and an intentional local artwork
  fallback.
- Preserved the existing three-note identify interaction as a temporary overlay
  above the Music view.
- Added client-entry comparison so a running kiosk reloads after deployment
  replaces its hashed production bundle.

## Implementation Walkthrough

### 1. Model Independent Room State

`coordinator/client/src/music.js` owns the small pure model used by the screen.
Connection events replace only `connection`, playback events replace only the
latest `playback` snapshot, and identify events replace only `interaction`.
Brief coordinator loss or room identification therefore cannot erase the last
accepted playback observation.

The same module projects playing position from the snapshot's `positionMs` and
`observedAt`, clamps it to zero and the item duration, formats elapsed time, and
accepts only HTTPS artwork URLs. Its behavior is covered without another
frontend dependency by Node's built-in test runner:

```sh
pnpm --dir coordinator/client test
```

### 2. Render The Music View

`coordinator/client/src/App.jsx` consumes the initial playback snapshot sent
after the event stream's `ready` event and all later `music.playback` events.
A loaded item produces a warm hi-fi composition with a large square sleeve,
oversized title and creator text, collection, playback state, and progress.
Playing progress updates once per second; paused progress remains fixed.

Stopped and unavailable snapshots render explicit empty states rather than
retaining stale metadata. A coordinator disconnect leaves valid playback
visible beneath a reconnect notice. Identify, completion, and failure use a
temporary full-screen overlay, so the existing visible pulse and generated
three-note WAV keep their interaction priority without becoming the persistent
channel.

The coordinator reads the built module entry from `index.html` and includes it
in each `ready` event. The client compares that path with its loaded module and
reloads when they differ. Replacing a production client therefore refreshes the
kiosk without restarting its whole endpoint session or disturbing PulseAudio.

`coordinator/client/src/styles.css` contains only the title clamp, local record
fallback, artwork edge treatment, and existing identify animation. Reduced
motion disables the repeating pulse and progress transitions.

### 3. Keep Remote Access Image-Only

The snapshot already contains a coordinator-validated HTTPS artwork URL. The
client loads that URL through `<img>` elements with no referrer and switches to
a local Cortex Home record mark if either load fails.

`coordinator/cortex_home.py` adds `https:` only to `img-src`. Its
`connect-src`, `media-src`, `script-src`, and `style-src` policies remain
unchanged, so artwork does not introduce another client API or executable
resource origin.

### 4. Build And Deploy

The complete production build and coordinator deployment still use the stable
entry point:

```sh
./coordinator/install homelab
```

The installer builds the fixed client, replaces the coordinator snapshot under
`/opt/cortex-home`, and restarts `cortex-home.service`. Chromium reconnects to
the restarted event stream automatically. Because coordinator playback state
is intentionally in memory, pause, resume, seek, or change the selected track
after deployment to publish the receiver's current item.

An endpoint still running the pre-GH-007 client does not understand the
client-entry handshake. Restart Chromium once after deploying this issue:

```sh
ssh -t <endpoint-ssh-host> \
  'sudo pkill -TERM -u cortex-endpoint -x chrome'
```

The endpoint session loop relaunches Chromium after two seconds. Later changed
client entries reload themselves through the accepted handshake.

## Problems Encountered

### 1. A Progress-Bounds Test Used The Wrong Clock

- Symptom: The first state-model run expected a deliberately negative playing
  position to remain at zero, but projection reached the duration cap.
- Diagnosis: The test omitted its clock argument, so it projected the old
  fixture timestamp all the way to the current time.
- Resolution: The bounds assertion now evaluates at the snapshot's
  `observedAt`, while separate assertions prove forward projection, negative
  clock skew, pause behavior, and the duration cap.
- Remaining caveat: None; all six focused tests pass.

### 2. Live Installation Requires Reviewer Sudo

- Symptom: The coordinator host is reachable over key-based SSH, but the
  deployment entry point cannot run unattended.
- Diagnosis: The remote host correctly requires an interactive password for
  `sudo`; no passwordless deployment permission is configured.
- Resolution: Keep deployment behind the existing reviewed
  `./coordinator/install homelab` command and let the reviewer enter
  the password directly. The reviewer confirmed the interactive deployment
  command completed.
- Remaining caveat: Interactive sudo remains an intentional deployment
  requirement.

### 3. The Identify Signal Was Too Loud

- Symptom: The correlated identify request completed and all three tones were
  audible, but the user found them uncomfortably loud.
- Diagnosis: Chromium and Raspotify share the endpoint user's PulseAudio sink,
  which reaches the same ALSA Master and Headphone controls. Endpoint
  provisioning previously set both controls to 70%.
- Resolution: Lower the shared Headphone control before repeating the signal:

  ```sh
  sudo amixer -c 0 sset Headphone 50% unmute
  ```

  This affects both identify and Spotify immediately. The user confirmed the
  repeated identify interaction was comfortable, and `endpoint/imac/provision-host`
  now reconstructs Headphone at 50%. Persist the current live mixer state with
  `sudo alsactl store 0`.
- Remaining caveat: Master remains at its accepted 70% setting. A later
  endpoint reprovision will apply the newly accepted 50% Headphone value. The
  user persisted the current live mixer state.

### 4. The Kiosk Kept The Replaced Client In Memory

- Symptom: The coordinator held live playing snapshots and Chromium remained
  connected, but the iMac still displayed `Room endpoint ready` and ignored
  Spotify changes.
- Diagnosis: Deployment replaced the hashed static assets and restarted the
  coordinator, but the unattended kiosk intentionally kept its existing page
  alive. The old GH-004 client reconnected its event stream and did not
  understand `music.playback`.
- Resolution: The coordinator now includes the current hashed client entry in
  `ready`; a client whose loaded entry differs reloads the page before
  accepting the connection.
- Remaining caveat: The old client required one manual restart after the fix
  was deployed. The user confirmed the restarted kiosk loaded the Music view;
  later changed builds can use the new self-refresh handshake.

## Heatmap

## Hot

### H1 - Keep Playback And Interaction State Separate

- Decision: Playback remains the persistent room view while connection and
  identify feedback occupy independent state.
- Where: `coordinator/client/src/music.js` and
  `coordinator/client/src/App.jsx`
- Why: A diagnostic interaction or brief reconnect must not invent a receiver
  transition or erase accepted now-playing state.
- Alternatives: Replace the whole view for every event; combine every event
  into one status enum; hide operational feedback.

### H2 - Project Progress Only In The Client

- Decision: Project playing position once per second from `positionMs` and
  `observedAt`.
- Where: `coordinator/client/src/music.js` and
  `coordinator/client/src/App.jsx`
- Why: The accepted snapshot contains enough information for useful progress
  without polling or increasing event frequency.
- Alternatives: Static progress; coordinator ticks; an unbounded CSS
  animation.

### H3 - Load Artwork Directly From HTTPS

- Decision: Permit HTTPS only in `img-src`, load artwork without a referrer,
  and fall back locally.
- Where: `coordinator/cortex_home.py` and
  `coordinator/client/src/App.jsx`
- Why: Proxying or caching would add storage and request lifecycle machinery
  without an offline-artwork requirement.
- Alternatives: Proxy or cache artwork; omit it; bind the client to one Spotify
  CDN hostname.

## Stylistic

### S1 - Warm Hi-Fi Sleeve Composition

- Choice: Use a large square sleeve, oversized editorial type, warm charcoal,
