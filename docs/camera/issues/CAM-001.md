# CAM-001: Present The Camera Mirror

Previous identifier: `GH-017`.

# What

- Added `camera` as the third explicit coordinator channel and
  `Ctrl`+`Alt`+`3` as its fixed keyboard shortcut.
- Added a full-screen, horizontally mirrored, video-only Camera channel with a
  persistent local-only label and shared room feedback above it.
- Bound camera capture to the observed Camera component lifetime, including
  complete track release on exit, reload, ended streams, failed attachment, and
  stale asynchronous results.
- Added explicit unsupported, exact-origin policy, permission-denied,
  unavailable, and ended-stream presentation with retry only after reentry.
- Added fake-stream lifecycle tests and documented the third channel in the
  coordinator operator guide.
- Rebased merged GH-014 and extended its generated exact-origin Chromium policy
  with unattended video capture for the same configured coordinator origin.
- Deployed the integrated client and exact-origin policy; the user confirmed
  that the physical iMac mirror works.
- Added a Camera-local screen ring light with off, warm, white, and cold modes,
  four bounded fade widths, and arrow-key controls.

# Implementation Walkthrough

`coordinator/cortex_home.py` now validates the fixed set `today`, `music`, and
`camera`. A successful Camera request follows the unchanged action sequence:
the coordinator publishes accepted action status, publishes
`channel.active: {"active": "camera"}`, and only then publishes completion.
Invalid values fail before the coordinator mutates its current channel.

`coordinator/client/src/room-state.js` maps only exact, non-repeated
`Ctrl`+`Alt`+`3` keydown events without Shift or Meta to the existing
`channel.select` action. `App.jsx` does not render Camera from that request or
its acknowledgement. It keeps rendering the old channel until the SSE reducer
receives the observed Camera snapshot, then uses the existing explicit channel
switch to mount `CameraChannel`.

`coordinator/client/src/CameraChannel.jsx` owns the visible Camera presentation.
Its video element is muted, inline, control-free, horizontally mirrored, and
uses cover cropping across the full display. The local mirror label remains
above the video while `RoomFeedback` stays outside the channel component at its
existing higher shared layers. Failure copy replaces video instead of leaving a
blank or frozen surface.

`coordinator/client/src/camera.js` owns one capture generation. It requests
exactly `{audio: false, video: true}`, validates that the returned stream has
video, and attaches only a still-current stream. Its cleanup detaches the
element and stops every returned track. A stale result stops itself. A track
ending releases all sibling tracks and shows the ended state. Page hide
performs the same cleanup for Chromium reload or exit. The component uses a
layout-effect cleanup so a transition away releases the Camera before the next
channel is painted. There is no automatic retry; remounting after deliberate
reentry creates the next single request.

`coordinator/client/src/camera.test.js`, `channels.test.js`,
`room-state.test.js`, and `coordinator/tests/test_coordinator.py` cover capture
ownership, stale resolution, ended streams, reload, reentry, explicit error
classification, mirror presentation, keyboard classification, and coordinator
state ordering. The implementation adds no canvas, recorder, upload, payload,
log, agent projection, or frontend dependency.

The same Camera component now owns temporary ring-light state. It starts at
`off` and medium width on every mount. Exact unmodified Left and Right keydowns
cycle `off → warm → white → cold → off`, with Left traversing the reverse
order. Exact Up and Down keydowns move across four responsive width bounds.
Repeat keydowns and modified arrows are ignored. Because the key listener
belongs to `CameraChannel`, these arrows have no Cortex Home behavior in Today
or Music. `styles.css` uses the outer half of the selected width as a solid
square frame that fills every screen corner. Only its inner opening is rounded;
an inset shadow fades through the inner half to the camera image. The overlay
never reads or modifies video frames.

After rebasing merged GH-014, `endpoint/imac/provision-host` and
`endpoint/imac/provision-media-host` now render the same root-owned
`/var/snap/chromium/current/policies/managed/cortex-home-media.json`. The JSON
contains `AudioCaptureAllowedUrls`,
`OverrideSecurityRestrictionsOnInsecureOrigin`, and
`VideoCaptureAllowedUrls`, each set to the single validated runtime coordinator
origin with one trailing slash. Tests reject wildcard, global video, and
all-media grants. The focused `provision-media` entry point reads the existing
origin from `/etc/cortex-endpoint/coordinator-url`, installs the policy, and
restarts the kiosk without changing packages, Wi-Fi, or unrelated endpoint
configuration.

To reconstruct the current implementation and run it locally:

```sh
pnpm --dir coordinator/client install --frozen-lockfile
python3 coordinator/cortex_home.py --host 127.0.0.1
pnpm --dir coordinator/client dev
```

The coordinator and Vite commands run in separate terminals. Loopback is a
browser secure context, so a development machine with a camera can exercise
the local capture flow.

Deploy the integrated client and focused endpoint media policy with:

```sh
ssh imac 'sed -n "1p" /etc/cortex-endpoint/coordinator-url'
./coordinator/install homelab
./endpoint/imac/provision-media
```

The first command resolves the deployed exact origin from its source of truth;
the focused media provision reads that file itself. Both installers require the
respective administrator's interactive sudo password.

Inspect the installed policy after provisioning:

```sh
ssh -t imac \
  'sudo python3 -m json.tool /var/snap/chromium/current/policies/managed/cortex-home-media.json'
```

# Problems Encountered

## 1. GH-014 policy boundary initially was not available

- Symptom: Neither the GH-014 worktree nor the remote contains implementation
  commits beyond the shared issue-planning baseline.
- Diagnosis: GH-017 is allowed to begin isolated component and channel work,
  but the accepted workflow explicitly prohibits it from creating a competing
  Chromium media policy before GH-014 merges.
- Resolution: Implemented and verified the independent work first. After GH-014
  merged, fetched main, rebased GH-017, resolved the GH-015 presentation and
  GH-014 voice overlaps, then extended the shared generated policy with only
  the video allowlist.
- Remaining caveat: None.

## 2. Worktree-local frontend packages were absent

- Symptom: The initial frontend test command could not resolve React.
- Diagnosis: This issue worktree had the committed lockfile but no local
  `node_modules`.
- Resolution: Ran
  `pnpm --dir coordinator/client install --frozen-lockfile`; pnpm reused the
  locked package store without changing the manifest or lockfile.
- Remaining caveat: Dependencies remain uncommitted, worktree-local build
  inputs.

## 3. Deployment requires two interactive sudo passwords

- Symptom: `./coordinator/install homelab` built the integrated
  production client and reached the ThinkPad sudo prompt, while both deployment
  hosts reject non-interactive `sudo -n`.
- Diagnosis: The repository installers correctly require administrator
  authentication; the development agent does not have either password.
- Resolution: Stopped the waiting SSH session without changing the ThinkPad.
  Recorded the exact two operator commands in the walkthrough. The user ran
  both installers, confirmed the physical mirror, and a follow-up read verified
  the integrated production asset and all three exact-origin policy entries.
- Remaining caveat: None.

# Heatmap

## Hot

### H1 - Let observed channel state authorize capture

- Decision: Mount capture only from the observed active Camera snapshot and
  release it synchronously on every transition away.
- Where: `App.jsx`, `CameraChannel.jsx`, and `camera.js`.
- Why: Request acceptance is not proof that the shared display changed, while
  camera lifetime must remain bounded to its visible channel.
- Alternatives: Start from keydown, start from action acknowledgement, or keep
  one background stream.

### H2 - Keep the mirror direct and local

- Decision: Attach the owned stream directly to one muted mirrored video
  element and expose no frame-processing boundary.
- Where: `CameraChannel.jsx` and `camera.js`.
- Why: Direct attachment provides the accepted local mirror without creating
  snapshots, recordings, coordinator payloads, or agent input.
- Alternatives: Canvas, recorder, endpoint streaming service, or retained
  background media.

### H3 - Extend the shared exact-origin media policy

- Decision: Add video permission to GH-014's generated policy for the same
  configured coordinator origin.
- Where: `endpoint/imac/provision-host` and
  `endpoint/imac/provision-media-host`.
- Why: Camera needs both a secure context and unattended kiosk permission,
  while a second policy file, wildcard, or global media flag would broaden or
  obscure sensor authority.
- Alternatives: Independent Camera policy, global browser flag, interactive
  prompt, or TLS migration in this issue.
