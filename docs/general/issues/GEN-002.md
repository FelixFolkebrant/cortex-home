# GEN-002: Organize Documentation By Module

# What

- Replace the project-wide Crossroads document hierarchy with module-owned
  IDEA, ROADMAP, active issue, and completed issue documentation.
- Give every module its own three-letter issue prefix and migrate existing
  records without rewriting Git history.
- Replace Planpoints and separate plan/review artifacts with detailed module
  roadmaps and one living issue document.

## Out Of Scope

- No product, runtime, deployment, or user-interface behavior changes.
- No rewriting of historical commits or branches.

## Dependencies

- None. This issue is the accepted project-wide documentation migration.

# Acceptance Criteria

- [x] General, Platform, Shell, Today, Music, Lighting, Voice, Camera, AirPlay,
  and Alarm have clear documentation homes and unique prefixes.
- [x] Every existing completed and active issue has one canonical module-owned
  record with its previous `GH` identifier preserved.
- [x] Each module has an IDEA and a ROADMAP that describe intended behavior,
  current behavior, direction, and durable decisions.
- [x] Planpoints, the Crossroads manifesto, Heatmap, Style, Patterns, and old
  templates are removed after useful content is incorporated.
- [x] Repository instructions and links use the new workflow and paths.
- [x] Local Markdown links resolve and no active document depends on the old
  directory structure.

# Approach And Decisions

- General is deliberately small. Platform owns coordinator and endpoint
  infrastructure; Shell owns behavior shared by channel views.
- Cross-module issues choose one primary module and link dependencies rather
  than duplicating records.
- Historical issue narratives may retain old branch and issue references when
  they describe what actually happened.

# Implementation Walkthrough

1. `docs/README.md` now indexes the ten documentation modules and assigns the
   `GEN`, `PLT`, `SHL`, `TOD`, `MUS`, `LGT`, `VOI`, `CAM`, `AIR`, and `ALA`
   prefixes.
2. Every module has an `IDEA.md` for purpose and boundaries, a `ROADMAP.md` for
   current and future direction, and local `issues/` and `wip/` directories.
   General additionally owns `WORKFLOW.md` and `templates/ISSUE.md`.
3. Existing `GH` records were moved to the module that owns their outcome and
   renumbered within that module. Each migrated record retains its former
   identifier directly below the heading; historical branch names and
   implementation prose remain unchanged when they describe real past work.
4. Active issue records are now `voice/wip/VOI-004.md`,
   `shell/wip/SHL-002.md`, and `alarm/wip/ALA-001.md`. Their separate plan files
   were folded into or superseded by the living records.
5. Useful direction from the old project roadmap, backlog, and seven Planpoints
   was incorporated into module roadmaps. The manifesto, Heatmap, Style,
   Patterns, Planpoints, old templates, global issue directories, and root
   backlog were then removed.
6. `README.md`, `AGENTS.md`, and `coordinator/README.md` now point to the module
   structure and current issue identifiers.

# Problems Encountered

- Moving historical issue files invalidated their relative Heatmap reference.
  The classification document is intentionally removed, so those reference
  lines were deleted while the useful historical decision sections remain.
- Initial path validation found several guessed endpoint filenames in new
  module briefs. They were corrected against the tracked repository paths
  before completion.

# Review Findings

- Completed historical records still mention old Planpoints, `GH` branches,
  and former paths when recounting the work as it happened. They are not active
  workflow dependencies and were preserved to avoid falsifying history.
