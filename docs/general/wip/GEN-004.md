# GEN-004: Convert Tracked JavaScript To TypeScript

# What

- Convert every tracked, authored JavaScript file in `coordinator/agent` and
  `coordinator/client` to TypeScript, including tests and the Vite
  configuration.
- Add the smallest TypeScript build and type-checking setup needed for the
  Node agent and Vite client.
- Preserve the existing runtime behavior, package entry points, tests, and
  development commands.

Before:

- The repository has 26 tracked authored `.js` files: seven in the agent and
  nineteen in the client.
- JavaScript checks validate syntax and formatting but do not type-check the
  codebase.

After:

- No tracked authored `.js` files remain in `coordinator/agent` or
  `coordinator/client`.
- Both packages type-check as part of their normal validation commands.
- The agent child-process entry points and the client production build retain
  their current behavior.

## Out Of Scope

- Converting Python, shell, CSS, or documentation files.
- Editing third-party dependencies, lockfile contents unrelated to TypeScript,
  or generated build output.
- Changing agent prompts, coordinator APIs, browser interactions, or product
  behavior while adding types.
- Reorganizing modules beyond import and entry-point changes required by the
  TypeScript runtime.

# Heatmap

### H1 - Keep the migration behavior-preserving

- Decision: Treat this as a source-language and tooling migration, not a
  refactor.
- Proposed approach: Preserve public exports, child-process launch shapes, and
  client behavior; make only the changes needed to express types and execute
  TypeScript sources.
- Why: The migration touches every JavaScript boundary, so unrelated changes
  would make regressions difficult to isolate.
- Alternatives: Combine the conversion with module redesign or allow unchecked
  JavaScript to remain at runtime boundaries.
- Review focus: Verify the Node agent entry points and Vite configuration still
  start through the existing documented commands.

# How to test

### Complete conversion

- **Start** - Install the pinned dependencies for both JavaScript packages.
- **Action** - Run each package's type check, test suite, and its existing
  build or syntax validation command; list tracked `.js` files with
  `git ls-files '*.js'`.
- **Expected** - Type checking, tests, and builds pass, and the tracked-file
  listing is empty.

### Agent entry points

- **Start** - Use the existing local agent development command or its automated
  child-process tests.
- **Action** - Exercise the normal agent turn, answer, dialogue, and local-agent
  entry-point paths.
- **Expected** - Each entry point starts and communicates with its parent using
  the same payload and lifecycle as before the conversion.

# Notes

- **Scope baseline** - `git ls-files '*.js'` counted 26 authored JavaScript
  files when this issue was created. Files under `node_modules` are not project
  sources and are deliberately excluded.
- **Ownership** - General owns this issue because the conversion spans the
  coordinator agent and all client modules without a meaningful single product
  module owner.
- **Implementation** - Renamed all 26 authored files to `.ts`, including the
  two dialogue files present on the current integration branch and the Vite
  configuration. Updated Python launchers, installer manifests, tests, and
  operational documentation to use the new agent entry-point paths.
- **Tooling** - Both packages use pinned TypeScript 5.9.3 with no-emit checks;
  the client keeps Biome as its first validation step. Node's built-in runner
  executes the converted `.test.ts` files directly on the pinned Node 24
  deployment runtime.
- **Checks** - `pnpm install --frozen-lockfile` in both packages; `pnpm check`
  and `pnpm test` in both packages; client `pnpm build`; affected coordinator
  Python tests; and `git ls-files` confirmed no tracked `.js` files remain in
  the two package directories.
