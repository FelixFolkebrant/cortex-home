# GEN-003: Make Issue Records Skimmable

# What

- **Short records** - Make the shared issue template easy to scan while keeping
  optional detail available in Notes.
- **Focused review** - Restore a small heatmap that points reviewers to choices
  involving judgment without recreating the former planning hierarchy.
- **Minimal UI guidance** - Record the current product-wide preference for
  sparse, temporary interface design.

Before:

- The issue template required many detailed sections for every change.
- The workflow rejected heatmaps even when one decision deserved extra review.
- The current minimal interface preference was not written down.

After:

- Issues lead with What, Before, After, Out Of Scope, Heatmap, How to test, and
  Notes.
- Crossroad and Hot entries identify decisions that deserve attention; Warm,
  Cold, and Stylistic labels remain optional shorthand.
- The documentation index asks views to show only information the interaction
  needs.

## Out Of Scope

- Rewriting completed historical issues into the new format.
- Restoring Planpoints, separate review documents, style catalogs, or pattern
  catalogs.
- Defining a finished visual design system.

# Heatmap

### H1 - Layer detail instead of requiring sections

- Decision: Keep a fixed short summary shape and place useful extra evidence in
  Notes.
- Proposed approach: Use bold lead-ins and concise test scenarios; add detail
  only when it helps reconstruction, review, or maintenance.
- Why: Reviewers can understand the issue quickly without losing important
  implementation evidence.
- Alternatives: Keep the former mandatory long form or leave every issue
  unstructured.
- Review focus: The template must stay useful for both small and substantial
  changes.

### H2 - Heat is optional review guidance

- Decision: Use heat to describe judgment, not importance or severity.
- Proposed approach: Require no heat entries when a change has no meaningful
  choice; use Crossroad or Hot entries when alternatives matter.
- Why: The map should save reviewer time rather than add process.
- Alternatives: No heatmap or a separate review artifact.
- Review focus: Heat must not recreate the removed Planpoint workflow.

# How to test

### Documentation workflow

- **Start** - Read `AGENTS.md`, `docs/general/WORKFLOW.md`, the issue template,
  and the heatmap guide in that order.
- **Action** - Create a small sample issue, then compare the four documents for
  conflicting required sections or obsolete file references.
- **Expected** - The sample is concise, the heatmap is optional, and every
  referenced active path exists.

# Notes

- **Compatibility** - Completed issues remain valid historical records even
  when they use the previous detailed template.
- **Scope** - This changes documentation practice only; it changes no product
  or runtime behavior.
- **Confirmation** - `git diff --check` passed, and active guidance contains no
  reference to the removed Planpoint, pattern, or style document paths.
