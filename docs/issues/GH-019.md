# GH-019: Add On-Demand AirPlay

# What

- Tested UxPlay 1.68.2 with a physical iPhone and the real iMac display, audio,
  window manager, and Chromium kiosk.
- Rejected a Chromium-over-mirror HUD after proving that whole-window opacity
  also fades the HUD and stock Chromium 150 keeps its web-content backing
  opaque even when the page and browser background request alpha.
- Added an explicit AirPlay channel and `Control`+`Option`+`4` shortcut. The
  shortcut opens a minimal control view; its Apple-style switch starts and
  stops UxPlay without leaving that view.
- Made every new UxPlay mirror window borderless, fullscreen, focused, and
  above Chromium with an Openbox application rule. The browser is the waiting
  screen while disconnected; the native mirror replaces it while connected.
- Renamed the advertised receiver to `Skärmen` and chose passwordless UxPlay.
  No PIN is displayed, pairing key is retained, or client identity is
  registered.
- Added UxPlay and its required GStreamer packages to both full and focused
  endpoint provisioning. A small loopback control bridge connects the browser
  switch to the native helper; no compositor, window watcher, or always-on
  receiver service was added.

# Acceptance Criteria

- [x] The record explains why stock Chromium cannot provide the requested

- [x] Each new mirror window is handled without polling, a compositor, or a

# Plan Diff

- The accepted plan was intentionally investigation-only. After the physical
  experiment, the user rejected calling the issue complete and expanded
  GH-019 to include the smallest production AirPlay vertical slice.
- The experiment first recommended Chromium above UxPlay at 75% whole-window
  opacity. A later per-pixel-alpha probe disproved that as a usable HUD:
  translucent Chromium also fades its content, while transparent CSS still
  receives an opaque white Chromium web-content backing.
- The implementation therefore puts UxPlay above Chromium only while a mirror
  exists, omits the HUD and compositor, and uses the browser only as a minimal
  receiver-control view.
- The original PIN proposal was removed after confirming that UxPlay's PIN
  flag is optional. The accepted home-LAN tradeoff is simpler passwordless
  discovery while the receiver is deliberately active.

# Implementation Walkthrough

## 1. Composition Decision

The physical iMac runs X11/Openbox at 1920×1200 with Chromium 150 and no
desktop compositor. Ubuntu's UxPlay 1.68.2 package successfully received an
iPhone mirror and sent its audio through the existing built-in PCI analog
PulseAudio/Sonos route.

The initial experiment put UxPlay below Chromium and ran `xcompmgr`. Setting
Chromium to 75% whole-window opacity made the mirror visible, but faded all
browser content by the same amount. That cannot provide an opaque HUD.

A later isolated probe started the compositor before Chromium. Chromium then
selected a 32-bit ARGB visual, but a CSS-transparent document,
`--default-background-color=00000000`, and the DevTools
`Emulation.setDefaultBackgroundColorOverride` each still produced an opaque
white web-content backing. Chromium's Linux browser widget requests
translucency, but its X11 visual manager only exposes the visual; that does not
make stock browser web content a per-pixel-transparent desktop window.

Electron and a separate native overlay could own a genuinely transparent
window, but would add another browser/runtime or custom application to a
4 GB, CPU-constrained endpoint. GH-019 therefore skips the HUD instead of
shipping that complexity.

## 2. Coordinator And Control View

`coordinator/cortex_home.py` accepts `airplay` as the fourth fixed
`channel.select` value.

`coordinator/client/src/AirPlayChannel.jsx` renders an AirPlay mark, the title
`AirPlay`, and an Apple-style switch. Off has no supporting copy. Starting
shows only a loader. On shows `Select tv Skärmen to cast screen`.
`coordinator/client/src/App.jsx` selects that presentation and hides shared room
feedback while it is active. The view participates in normal channel layout
rather than positioning itself as an overlay. Plain, non-repeating `Enter`
toggles the switch only while the AirPlay view is mounted.

`coordinator/client/src/room-state.js` maps `Control`+`Option`+`4` to AirPlay
for browser-only development. On the iMac, Openbox owns the chord globally and
selects the control view without starting the native receiver.

## 3. Endpoint Lifecycle

`endpoint/imac/files/cortex-endpoint-airplay` owns the native lifecycle:

- `receiver-on` creates a private HOME below the graphical user's
  `XDG_RUNTIME_DIR`, starts `/usr/bin/uxplay`, and waits for it to remain alive.
- `receiver-off` interrupts UxPlay, removes its PID and temporary HOME, and
  restores the accepted audio route without changing the selected channel.
- `status` reports only `on` or `off`.
- `airplay` selects the AirPlay view without starting the receiver.
- `stop-local` performs only local cleanup for endpoint-session shutdown.

The exact receiver options are:

```sh
/usr/bin/uxplay \
  -n "Skärmen" \
  -nh \
  -fs \
  -s 1920x1200 \
  -as pulsesink
```

There is deliberately no `-pin` or `-reg`. Omitting `-pin` disables UxPlay PIN
authentication. The temporary HOME also prevents receiver state from becoming
durable between activations.

`endpoint/imac/files/openbox-rc.xml` binds `C-A-4` to the AirPlay view. It owns
`C-A-1`, `C-A-2`, and `C-A-3` globally so selecting Today, Music, or Camera
stops UxPlay before posting the new channel. Its application rule matches the
named `Skärmen.GStreamer` window and applies `decor=no`, `focus=yes`,
`layer=above`, and `fullscreen=yes`. GStreamer creates a fresh X11 window after
every mirror connection, so a declarative Openbox rule handles reconnection
without `wmctrl`, polling, or a window watcher.

`endpoint/imac/files/cortex-airplay-control` binds only
`127.0.0.1:38019`. It accepts the configured coordinator origin and exposes
only status, on, and off. Chromium's content-security policy permits only that
loopback control origin in addition to the coordinator itself. The bridge uses
one Bash supervisor and the already-installed OpenBSD netcat listener rather
than another browser runtime. A transient endpoint sample observed about
2 MiB RSS and 0% sampled idle CPU for netcat; the complete bridge is
approximately 6 MiB with its supervising Bash process.

`endpoint/imac/files/cortex-endpoint-session` starts the bridge, checks that it
remains alive, and calls `stop-local` before the graphical session exits. It
does not start UxPlay at login.

## 4. Provisioning

`endpoint/imac/provision-host` installs the receiver during full endpoint
provisioning. `endpoint/imac/provision-media` is the focused deployment path
for an existing endpoint; its remote `provision-media-host` installs:

```text
uxplay
gstreamer1.0-plugins-bad
gstreamer1.0-plugins-base
gstreamer1.0-plugins-good
gstreamer1.0-pulseaudio
gstreamer1.0-x
netcat-openbsd
```

The stripped iMac currently reports 135 new packages in an `apt-get -s`
simulation because the codec stack has a broad dependency tree. Those
installed files use disk space but no CPU or resident memory while UxPlay is
stopped. No `xcompmgr`, `wmctrl`, Electron, or separate HUD runtime is
installed.

Deploy the coordinator first, then the focused endpoint changes:

```sh
./coordinator/install <server-ssh-host>
./endpoint/imac/provision-media
```

The coordinator installer needs the server's sudo access. The endpoint command
uses the existing `imac` SSH alias and asks for that account's sudo password.
It restarts the kiosk session.

## 5. Operation And Recovery

To start:

1. Press `Control`+`Option`+`4`.
2. The browser should show only the AirPlay title and an off switch.
3. Press `Enter` or click the switch. It should show a loader and then
   `Select tv Skärmen to cast screen`.
4. On the iPhone, open Control Center, choose Screen Mirroring, then choose
   `Skärmen`.
5. No code should be requested. Once connected, the native mirror should be
   borderless, fullscreen, and above the waiting page.

Stopping Screen Mirroring on the iPhone reveals the AirPlay control page and
keeps UxPlay available for another connection. Press `Enter` again or click the
switch to stop the receiver without leaving AirPlay, or select Today, Music, or
Camera to stop it and change views.

If the local bridge cannot be reached, the view shows `AirPlay control is
unavailable.` and returns the switch to off. A receiver launch failure shows
the helper's short error instead. To perform local recovery from the graphical
endpoint session:

```sh
/usr/local/bin/cortex-endpoint-airplay stop-local
```

The control view reconciles the actual receiver status whenever it loads.

## 6. Resource Boundary

The earlier ten-second moving-mirror sample observed approximately 16–56%
UxPlay CPU and 87–90 MiB resident memory. A relatively static mirror observed
approximately 132 MiB. The prior compositor used another 8 MiB; it is not part
of this implementation.

When the switch is off, UxPlay is absent. The Bash/netcat loopback bridge
remains with roughly 6 MiB expected RSS and no sampled idle CPU so Chromium
can operate the switch. A final deployed check must confirm both that small
idle boundary and UxPlay's absence.

# Problems Encountered

## 1. The Minimal UxPlay Package Was Not A Complete Runtime

- Symptom: UxPlay printed help but could not start because GStreamer could not
  discover required playback, parser, and output plugins.
- Diagnosis: Ubuntu's UxPlay dependency did not pull every runtime plugin group
  needed on the stripped endpoint.
- Resolution: Provision the five explicit GStreamer runtime groups used by the
  successful physical experiment.
- Remaining caveat: The codec dependency tree adds 135 packages on the current
  endpoint, although they are idle files rather than background processes.

## 2. A One-Time Window Command Failed On Reconnect

- Symptom: UxPlay's native window initially had framing, published X11 PID `0`,
  and every reconnect created a fresh window above Chromium.
- Diagnosis: PID lookup and a stored X11 window ID cannot own GStreamer's
  connection-scoped window.
- Resolution: Match the explicit receiver name and GStreamer class in an
  Openbox application rule that applies to every new window.
- Remaining caveat: Changing the UxPlay receiver name requires changing the
  application rule at the same time.

## 3. Whole-Window Chromium Opacity Could Not Produce A HUD

- Symptom: A compositor and 75% Chromium opacity revealed UxPlay, but faded
  Today, controls, and feedback too.
- Diagnosis: `_NET_WM_WINDOW_OPACITY` applies to the complete top-level window,
  not selected CSS pixels.
- Resolution: Tested Chromium per-pixel transparency before choosing a final
  composition.
- Remaining caveat: Whole-window opacity remains unsuitable for opaque HUD
  content.

## 4. Stock Chromium Kept Transparent CSS Opaque

- Symptom: A depth-32 Chromium window still showed an opaque white backing
  behind a transparent page under command-line and DevTools background
  overrides.
- Diagnosis: An ARGB X11 visual does not make stock visible browser web
  contents an OS-level transparent surface.
- Resolution: Rejected Chromium-over-mirror HUD composition and put the native
  mirror above Chromium only while connected.
- Remaining caveat: A future HUD requires a native transparent overlay,
  Electron-style transparent window, browser patch, or a different video
  composition boundary.

## 5. Passwordless Discovery Trades Authentication For Simplicity

- Symptom: Displaying a random PIN would require parsing transient UxPlay
  output and sending secret state into the browser.
- Diagnosis: UxPlay PIN authentication is optional; a trusted-home-LAN
  receiver does not technically require it.
- Resolution: Omit `-pin`, retain no pairing state, and advertise `Skärmen`
  only while the operator has turned on the AirPlay switch.
- Remaining caveat: Any device on the same LAN can connect during that active
  window. Reintroduce PIN handling if the network is no longer trusted.

## 6. The Browser Could Not Start A Native Receiver Directly

- Symptom: The requested on-screen switch runs inside remote Chromium content,
  which cannot execute the endpoint helper.
- Diagnosis: The existing coordinator action changes room state but has no
  local process boundary, and adding Electron or a native UI would recreate
  the resource problem already rejected.
- Resolution: Added a loopback-only Bash/netcat bridge scoped to the configured
  coordinator origin and three fixed operations.
- Remaining caveat: The bridge adds roughly 6 MiB idle RSS. The final
  deployment confirmed private-network access in Chromium.

## 7. Chromium Exposed A Raw Fetch Failure

- Symptom: The deployed AirPlay view showed `Failed to fetch` even though the
  origin-bound loopback listener was running.
- Diagnosis: Private-network access sends an OPTIONS preflight and immediately
  opens the real request. The one-shot netcat listener has a millisecond-scale
  replacement gap between those connections.
- Resolution: Retry one network failure after 75 ms and replace browser-native
  error text with `AirPlay control is unavailable.` if the retry also fails.
- Remaining caveat: The bridge remains deliberately serial; it is sufficient
  for this single switch but is not a general local API.

## 8. Pre-Optimization Integration Runs Left Test Listeners

- Symptom: The final process check found three parentless netcat listeners on
  random high ports in addition to the deployed listener on port 38019.
- Diagnosis: Their start times and generated ports identified them as remnants
  of remote integration runs made before the bridge switched from a Bash
  coprocess wrapper to direct netcat.
- Resolution: Removed the three explicit test processes and confirmed that only
  the production bridge's 1.9 MiB loopback listener remained.
- Remaining caveat: Remote integration runs must use the current direct-netcat
  bridge; older copied scripts should not be run again.

# Heatmap

Reference: `../project/HEATMAP.md`.

## Hot

### H1 - Native Mirror Replaces Chromium While Connected

- Decision: Keep Chromium as the minimal AirPlay control screen, then let the
  native UxPlay window cover it during a connection.
- Where: `openbox-rc.xml`, `cortex-endpoint-airplay`, and
  `AirPlayChannel.jsx`.
- Why: Stock Chromium did not provide usable per-pixel desktop transparency,
  and the endpoint does not justify another HUD runtime.
- Alternatives: Whole-window translucency, Electron/native HUD, patched
  Chromium, or no AirPlay.

### H2 - Receiver Exists Only While The Switch Is On

- Decision: Use an on-screen switch backed by a loopback-only control bridge;
  do not autostart UxPlay.
- Where: `AirPlayChannel.jsx`, `cortex-airplay-control`,
  `cortex-endpoint-airplay`, and `cortex-endpoint-session`.
- Why: Mirroring is expensive on this hardware, while installed codec
  libraries cost no CPU or RAM when the process is absent.
- Alternatives: Always-on discovery, a larger local app, a remote coordinator
  process command, or manual recovery-terminal commands.

### H3 - No AirPlay PIN On The Trusted Home LAN

- Decision: Omit both `-pin` and `-reg`, show no password, and remove the
  receiver's temporary HOME on stop.
- Where: `cortex-endpoint-airplay` and `AirPlayChannel.jsx`.
- Why: This removes secret transport and persistence from a mode that is
  exposed only after a deliberate local shortcut.
- Alternatives: Parse and publish an ephemeral random PIN or retain registered
  client identities.

## Warm

- `coordinator/cortex_home.py`: `airplay` expands a deliberately fixed channel
  enum.
- `endpoint/imac/provision-media-host`: focused media provisioning now changes
