# GH-004: Identify The Room Endpoint

# What

- Added a dependency-free ThinkPad coordinator for one allow-listed
  `endpoint.identify` action and one connected room endpoint.
- Added a React and Tailwind full-screen client that receives correlated events,
  owns the visual and audible identify response, and reports completion or
  failure.
- Added fixed systemd installation and iMac provisioning paths, including a
  LAN-scoped UFW rule when the host firewall is active.
- Deployed the coordinator and client, proved one live correlated request, and
  recorded the real-client resource baseline.

# Plan Diff

- The accepted frontend stack was decided during implementation. The initial
  dependency-free prototype was replaced with React, Vite, Tailwind CSS, pnpm,
  `clsx`, CVA, `tailwind-merge`, and Biome before deployment.
- The ThinkPad's active UFW policy blocked the endpoint despite the coordinator
  listening on the LAN. Installation now derives the directly connected subnet
  and adds a port 8080 rule scoped to that LAN.
- Chromium created a healthy, unmuted PulseAudio stream for Web Audio but
  supplied only zero-valued samples. The client now generates an in-memory PCM
  WAV and plays it through the browser media path, while the kiosk starts the
  per-user PulseAudio bridge required by the Chromium Snap.
- The initial PCM media attempt failed explicitly because the client's content
  security policy did not allow its `blob:` audio source. The policy now allows
  only `blob:` media, with an HTTP boundary test covering that requirement.
- A short mono PCM signal reached the PulseAudio sink but did not produce a
  recognizable Sonos response. The final signal uses native stereo samples and
  three 0.8-second notes so the line-in has enough level and time to reproduce
  all three clearly.
- Power draw remains unmeasured because no measurement method is currently
  available.
- At the user's direction, the remaining across-room state review, controlled
  host reboots, and subjective real-client fan check do not block GH-004
  closure. They remain unchecked so the record does not invent reviewer
  confirmations.

# Heatmap

Reference: `../project/HEATMAP.md`.

## Hot

### H1 - Use Plain HTTP And Server-Sent Events

- Decision: Keep one caller request open while a server-sent event delivers the
  action and an endpoint callback resolves it.
- Where: `coordinator/cortex_home.py`.
- Why: One server-to-endpoint event does not justify a framework, WebSocket
  dependency, or broker.
- Alternatives: WebSockets; polling; a broker; separate submit and status
  requests.

### H2 - Keep One Explicit In-Memory Lifecycle

- Decision: Allow only `endpoint.identify` and retain bounded, correlated state
  in memory.
- Where: `coordinator/cortex_home.py`.
- Why: The temporary identify action needs honest acknowledgement, completion,
  failure, and timeout without inventing a reusable workflow engine.
- Alternatives: Fire-and-forget actions; durable records; generic event
  envelopes.

### H3 - Let The React Client Own Identify Feedback

- Decision: The full-screen client generates an in-memory PCM WAV, synchronizes
  its visual state with browser media playback, and waits for the media `ended`
  event before reporting completion.
- Where: `coordinator/client/src/App.jsx`.
- Why: The component directly observes both effects and can report their
  outcome without another endpoint daemon. Live Pulse monitoring showed that
  Chromium's Web Audio stream contained only zero-valued samples on this host.
  The stereo media signal then produced nonzero samples and all three notes
  through the Sonos.
- Alternatives: Web Audio oscillators; a separate ALSA service;
  coordinator-triggered audio.

### H4 - Install Fixed Runtime Files

- Decision: Build locally, copy fixed runtime files under `/opt/cortex-home`,
  install a systemd unit, and scope active UFW access to the directly connected
  LAN.
- Where: `coordinator/install` and `coordinator/install-host`.
- Why: The coordinator boots from a reviewable snapshot without turning the
  repository checkout into production state or publishing host identity.
- Alternatives: Run from the checkout; containerize; add configuration
  management.

# Notes

- The first live deployment exposed a missing LAN firewall rule. The installed
  service was healthy, but the iMac timed out until UFW allowed the local
  subnet. The installer now handles this case.
- Direct ALSA and PulseAudio tones both reached the Sonos. Chromium used the
  same default hardware sink at full, unmuted volume, but its Web Audio stream
  measured a zero peak and zero RMS, isolating the failure above PulseAudio.
- The first PCM media request failed with HTTP 502 because `default-src 'self'`
  blocked the generated `blob:` WAV. Adding the narrow `media-src blob:`
  directive changed the same request to a correlated HTTP 200 completion.
- The short mono PCM signal then measured nonzero at the sink but was not
  recognizable through the Sonos. Native stereo avoided the mono conversion,
  and lengthening the notes from 0.28 to 0.8 seconds produced three clear rising
  notes.
- The first request proved the temporary identify lifecycle only. A second real
  action must exist before its request and event shapes become an accepted
  reusable pattern.
- Across-room presentation states, subjective fan noise, and controlled host
  reboots remain reviewer-owned confirmations.
