# GH-025: Interruptible Voice Turns

# What

- Turned the IdeaPad-only local voice workbench into a persistent terminal loop
  that waits at `ready`, runs one bounded turn after Enter, and returns to
  `ready` after completion, failure, or cancellation.
- Kept each turn independent with one fresh cancellation event and one fresh
  Pi child request ID. No audio, transcript, answer, or conversation history is
  retained between turns.
- Hardened every phase handoff so a cancelled capture, transcript, answer, or
  synthesis result cannot advance to the next component or begin stale
  playback.
- Added focused tests for repeated turns, every cancellation phase, late-result
  rejection, fresh request IDs, process and pipe release, and successful
  recovery without credentials, network, speech models, or audio hardware.

# Plan Diff

- `Ctrl`+`C` while waiting at `ready` now exits cleanly like EOF instead of
  exposing a Python `KeyboardInterrupt` traceback. Active-turn `Ctrl`+`C`
  continues to cancel only that turn.
- Cancellation during in-process Vosk transcription or Pocket TTS synthesis is
  observed immediately after that synchronous call returns. Its result is
  discarded and can never reach the next phase, but the inference call itself
  is not preempted. A later fluency issue must introduce a cancellable inference
  boundary if physical qualification shows that delay is perceptible.
- The reviewer approved GH-025 for merge without recording a new private
  provider and audible interruption pass. The detailed physical checklist
  remains unchecked and becomes explicit input to the next fluent-core issue.

# Implementation Walkthrough

## 1. Keep One Terminal Runner Alive

`coordinator/local_voice.py` reports `ready` before each turn and waits for one
terminal input. Enter creates one new `threading.Event`, temporarily maps
`SIGINT` to that event, and runs the existing local interaction. Completion,
content-free failure, and cancellation all return through the same readiness
boundary. EOF or `Ctrl`+`C` at readiness exits cleanly, and the prior signal
handler is restored after every turn.

The runner remains local to the foreground IdeaPad process. It imports no
coordinator, endpoint, Hue, browser, or deployment client and opens no home
service connection.

## 2. Reject Every Cancelled Phase Result

`run_interaction` checks the current turn event before capture and after
capture, Vosk transcription, the Pi child answer, and Pocket TTS synthesis.
`AlsaInput`, `LocalAgent`, and `AlsaOutput` continue polling the same event while
their subprocesses run. Cancellation terminates the current process group,
waits for it, closes its pipes, and prevents any returned value from entering a
later phase.

`LocalAgent.answer` creates its request ID inside each call. A cancelled turn
therefore cannot share an ID with its successor, and the existing exact child
response validation rejects a stale response.

## 3. Run The Workbench

Follow the dependency and Vosk-model setup in `coordinator/README.md`. With the
private OpenRouter key present only in the current shell, start the repeated
loop from the repository root:

```sh
OPENROUTER_API_KEY=<private-key> \
  .venv/bin/python coordinator/local_voice.py \
  --vosk-model "$HOME/.local/share/cortex-home/vosk-model-small-en-us-0.15"
```

Use `arecord -L` and `aplay -L` to find an explicit device when the defaults are
not correct, then append `--input-device <alsa-name>` or
`--output-device <alsa-name>`. No deployment command or Cortex Home service is
required.

# Problems Encountered

## 1. Readiness Was Not An Accepted Phase

- Symptom: The first repeated-loop implementation failed before accepting a
  turn because `report_phase("ready")` rejected its own new phase.
- Diagnosis: `ready` was added to the runner before it was added to the fixed
  content-free phase allowlist.
- Resolution: Added `ready` to `PHASES` and a focused reporting test.
- Remaining caveat: None.

## 2. A Cancelled Synthesis Relied On The Output Boundary

- Symptom: Cancellation that arrived during synthesis was rejected by the real
  ALSA output boundary, but `run_interaction` could still pass the stale WAV to
  another output implementation.
- Diagnosis: There was no cancellation check between returned synthesis and
  `output_boundary.play`.
- Resolution: Added the same explicit post-result guard used at every earlier
  phase and covered it with a synthesizer that cancels while returning audio.
- Remaining caveat: Pocket TTS still completes its current synchronous call
  before the guard can discard the result.

## 3. Ready-State Interrupt Exposed A Traceback

- Symptom: `Ctrl`+`C` cancelled an active turn correctly but raised an unhandled
  `KeyboardInterrupt` when the loop was waiting for Enter.
- Diagnosis: The readiness boundary handled terminal EOF but not the terminal's
  ordinary interrupt exception.
- Resolution: Treat readiness `KeyboardInterrupt` as a clean local exit while
  retaining event-based cancellation during an active turn.
- Remaining caveat: None.

# Heatmap

Reference: `../project/HEATMAP.md`.

## Hot

### H1 - One Local Turn Owns The Next Turn

- Decision: Keep exactly one active local turn with a fresh cancellation event
  and Pi request ID. Do not overlap, queue, or resume turns.
- Where: `coordinator/local_voice.py` and
  `coordinator/tests/test_local_voice.py`.
- Why: A cancelled answer or WAV must never take over after the user starts a
  new utterance.
- Alternatives: Parallel turns, queued utterances, hands-free barge-in, and a
  microphone retained between turns.

### H2 - Keep Deliberate Local Sensing

- Decision: Enter starts one bounded capture and active-turn `Ctrl`+`C` cancels
  it; the microphone is not kept open at readiness.
- Where: `coordinator/local_voice.py` and `coordinator/README.md`.
- Why: GH-025 proves repeated lifecycle ownership without adding ambient
  sensing before the core local loop is qualified.
- Alternatives: Wake word, continuous listening, voice activity detection, and
  automatic turn start.

## Cold
