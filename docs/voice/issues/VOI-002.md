Previous identifier: `GH-014`.

# What

- Added one exact `Ctrl`+`Alt`+`Space` hold-to-capture boundary to the room
  client with a compact bottom bar for the requesting, listening, captured, or
  failed state. The active channel remains visible and the listening bar width
  responds to the captured signal level.
- Added a 15-second, 16 kHz mono signed 16-bit PCM WAV capture boundary that
  closes every owned track on release, focus loss, cancellation, error,
  reconnection, or client cleanup.
- Rendered Chromium's current secure-context override and audio-capture
  allowlist from the configured coordinator origin during iMac provisioning.
- Pinned Vosk, quantized `whisper.cpp`, Piper, and Pocket TTS qualification
  candidates and added an isolated ThinkPad installer.
- Added small engine-neutral recognizer and synthesizer contracts, explicit
  PCM validation, anonymous-memory Whisper input, bounded engine failures, and
  Vosk and Pocket TTS role selections.
- Added a content-free qualification command that reports aggregate accuracy,
  latency, CPU, memory, model size, output duration, and endpoint use without
  reporting utterances, answer text, paths, or host identity.
- Added endpoint-global `Ctrl`+`Alt`+`Up` and `Ctrl`+`Alt`+`Down` bindings that
  adjust only the pinned Sonos analog output by 5 percentage points.

# Implementation Walkthrough

## 1. Render One Exact Chromium Media Origin

`endpoint/imac/provision-host` already validates one local HTTP coordinator
origin and removes its optional trailing slash. It now derives the one
trailing-slash policy origin and writes:

```text
/var/snap/chromium/current/policies/managed/cortex-home-media.json
```

The root-owned file contains only
`OverrideSecurityRestrictionsOnInsecureOrigin` and
`AudioCaptureAllowedUrls`, each with that exact origin. It contains no
wildcard, deployment identity, video permission, or general media-approval
flag. The former `UnsafelyTreatInsecureOriginAsSecure` name was not used
because Chromium replaced it with the current override policy.

Reprovision the endpoint through the existing entry point:

```sh
./endpoint/imac/provision
```

For an already provisioned endpoint, install only the media policy from its
existing coordinator URL and restart the kiosk:

```sh
./endpoint/imac/provision-media
```

Inspect only the rendered policy:

```sh
ssh -t imac \
  'sudo python3 -m json.tool /var/snap/chromium/current/policies/managed/cortex-home-media.json'
```

## 2. Own Capture With The Held Chord

`coordinator/client/src/voice-capture.js` classifies only the initial exact
`Ctrl`+`Alt`+`Space` keydown. Releasing Space, either Control key, or either Alt
key ends the chord even when modifier flags have already changed. Repeats and
combinations containing Shift or Meta are ignored.

`VoiceCapture` requests audio with mono, 16 kHz, echo-cancellation-off,
noise-suppression-off, and automatic-gain-off constraints. Chromium's
`AudioContext` is required to expose 16 kHz or capture fails explicitly.
`pcm-capture-worklet.js` averages any supplied input channels into mono and
returns only float samples to the owning page. `createPcmWav` bounds and
converts those samples to this exact interchange shape:

| Property | Value |
|---|---|
| Container | WAV |
| Encoding | Signed 16-bit little-endian PCM |
| Channels | 1 |
| Sample rate | 16,000 Hz |
| Maximum capture | 15 seconds |

Every stream has one generated request ID. A late `getUserMedia` result stops
its tracks when release or cancellation already invalidated that request.
Release, blur, coordinator reconnection, error, the 15-second timer, and React
cleanup all stop every owned track. The completed WAV is deliberately
discarded in GH-014; GH-016 will submit it inside the complete interaction
lifecycle rather than introducing a qualification-only product API.

`App.jsx` serializes capture with existing room actions.
`RoomFeedback.jsx` makes microphone acquisition, active listening, release, and
failure visible in a compact bottom overlay without replacing either channel
or adding an agent response. While listening, `VoiceCapture` maps the current
PCM root-mean-square level from approximately -60 dB to -12 dB onto the bar
width and limits visual updates to 20 per second. Audio remains in the same
in-memory capture path and the level calculation adds no new retention or
network boundary.

## 3. Keep Speech Engines Behind Two Contracts

`coordinator/speech.py` defines:

```python
class Recognizer(Protocol):
    def transcribe(self, audio: WaveAudio) -> str: ...

class Synthesizer(Protocol):
    def synthesize(self, text: str) -> WaveAudio: ...
```

`read_capture` rejects anything other than the documented browser shape and
15-second bound. Synthesized WAV is independently limited to mono signed
16-bit PCM and 60 seconds. Text and transcript sizes are bounded, and all
candidate failures become a generic `SpeechError` without forwarding backend
logs or output.

The selected `VoskRecognizer` consumes validated PCM frames and the selected
`PocketTtsSynthesizer` returns the same engine-neutral `WaveAudio` value.
The Whisper candidate passes WAV through a Linux anonymous memory file, so its
qualification does not need a persisted recording. The Piper candidate
implements the identical synthesizer contract. Coordinator behavior does not
receive any candidate model, recognizer, tensor, or voice object.

The candidate and initial selected-role pins live in
`coordinator/speech-candidates.json`:

| Role | Candidate | Exact pin |
|---|---|---|
| Recognition | Vosk | `0.3.45`, `vosk-model-small-en-us-0.15` |
| Recognition | whisper.cpp | `1.9.1`, `ggml-base.en-q5_1.bin` |
| Synthesis | Piper | `1.5.0`, `en_US-lessac-medium` |
| Synthesis | Pocket TTS | `2.1.0`, English `alba` |

The current selection is Vosk plus Pocket TTS. Vosk tied whisper.cpp on
aggregate accuracy while using less latency, CPU, and memory. Pocket TTS won
the real Sonos listening comparison decisively. whisper.cpp and Piper remain
installed as qualification candidates so GH-016 can revisit either single pin
if full-turn latency changes the decision. No runtime switching is introduced.

## 4. Install And Measure Candidates In Isolation

Install all candidates on the ThinkPad:

```sh
./coordinator/install-speech <server-ssh-host>
```

`coordinator/install-speech-host` creates an isolated
`/opt/cortex-speech/qualification-venv`, builds the pinned `whisper.cpp` release
with OpenBLAS, installs the exact Python packages, downloads the exact models,
and verifies the Vosk, Whisper, and Piper model checksums. It does not change
the production coordinator virtual environment or service.

Open a ThinkPad session with the operator's existing SSH agent forwarded and
accept the endpoint host key before playback. Do not copy an operator private
key onto the ThinkPad:

```sh
ssh -A <server-ssh-host>
ssh -o StrictHostKeyChecking=accept-new imac@imac.local true
```

Endpoint playback uses one root-owned, argument-free qualification helper
through a command-specific sudo rule. It reads WAV from standard input as the
`cortex-endpoint` user and exports only that user's existing PulseAudio socket.
It does not store audio, accept a general command, or start a service.

Recognition capture uses the matching argument-free helper. It emits one fixed
15-second, 16 kHz mono signed 16-bit PCM WAV from `plughw:S330` to standard
output. The ThinkPad holds it only in a private RAM-backed directory while the
two fresh recognizer processes read the same utterance, then removes it.

Create the private manifest and bounded captures outside the repository as
documented in `coordinator/README.md`. Run all four candidates in separate
fresh processes:

```sh
/opt/cortex-speech/qualification-venv/bin/python \
  /opt/cortex-speech/qualify_speech.py recognition \
  --backend vosk \
  --manifest /tmp/cortex-speech/manifest.json \
  --model /opt/cortex-speech/models/vosk-model-small-en-us-0.15

/opt/cortex-speech/qualification-venv/bin/python \
  /opt/cortex-speech/qualify_speech.py recognition \
  --backend whisper.cpp \
  --manifest /tmp/cortex-speech/manifest.json \
  --model /opt/cortex-speech/models/ggml-base.en-q5_1.bin

/opt/cortex-speech/qualification-venv/bin/python \
  /opt/cortex-speech/qualify_speech.py synthesis \
  --backend piper \
  --manifest /tmp/cortex-speech/manifest.json \
  --model /opt/cortex-speech/models/en_US-lessac-medium.onnx \
  --endpoint imac@imac.local

/opt/cortex-speech/qualification-venv/bin/python \
  /opt/cortex-speech/qualify_speech.py synthesis \
  --backend pocket-tts \
  --manifest /tmp/cortex-speech/manifest.json \
  --model /opt/cortex-speech/pocket-cache \
  --voice alba \
  --endpoint imac@imac.local
```

The command emits only aggregate metrics. Remove the private manifest and
audio inputs immediately after both recognizers finish. Do not commit or paste
the utterances, transcripts, answers, raw command output, hostname, or
recordings into this record.

# Problems Encountered

## 1. Chromium Replaced The Planned Secure-Context Policy Name

- Symptom: The older `UnsafelyTreatInsecureOriginAsSecure` policy described by
  its launch flag is no longer supported by current Chromium.
- Diagnosis: Chromium removed it in M69 and gives the current browser-level
  policy the name `OverrideSecurityRestrictionsOnInsecureOrigin`.
- Resolution: Provisioning renders the current policy together with
  `AudioCaptureAllowedUrls`.
- Remaining caveat: The generated endpoint JSON contains the configured exact
  origin under both policies; Chromium's effective process state and unattended
  capture were confirmed after restart.

## 2. Ubuntu's Chromium Is A Snap

- Symptom: Upstream Chromium's default managed-policy directory does not match
  the endpoint's `/snap/bin/chromium` package.
- Diagnosis: The Snap reads system policy from its data path rather than the
  ordinary `/etc/chromium/policies` directory.
- Resolution: Provisioning owns the root-writable
  `/var/snap/chromium/current/policies/managed/cortex-home-media.json` path.
- Remaining caveat: The live Chromium process confirms the generated origin is
  effective; future browser upgrades should still be checked through
  `chrome://policy`.

## 3. Qualification Required The Shared Physical Room

- Symptom: The development machine could not supply the ThinkPad CPU, Anker room
  acoustics, iMac browser policy, or Sonos listening judgment required by the
  plan.
- Diagnosis: Those criteria deliberately depend on the shared physical room.
- Resolution: Added exact isolated installation and content-free measurement
  commands, then ran both recognizers on the same Anker captures and both
  synthesizers through the real Sonos route. The reviewer selected Vosk and
  Pocket TTS from the recorded results.
- Remaining caveat: All shared-room checks passed. First-audio and interrupted
  stop were bounded but no finer manual stopwatch value was retained.

## 4. Remote Installation Requires Interactive Sudo

- Symptom: The speech installer reached the remote sudo password prompt before
  creating `/opt/cortex-speech`.
- Diagnosis: The target is the required Ubuntu 24.04 host and is reachable, but
  its sudo policy deliberately requires a credential that must remain with the
  operator.
- Resolution: Stopped the attempted install without handling or recording the
  password. The operator ran
  `./coordinator/install-speech <server-ssh-host>` from an interactive
  terminal using the private server SSH alias; the installed
  executable, models, voices, and isolated environment were then verified
  without sudo.
- Remaining caveat: The final rerun deployed and remotely confirmed the Vosk
  plus Pocket TTS selection.

## 5. The ThinkPad Does Not Own The Workstation SSH Alias

- Symptom: Endpoint playback failed before audio because `imac` is an alias in
  the development workstation's SSH configuration, not a resolvable ThinkPad
  host.
- Diagnosis: `imac.local` resolves from the ThinkPad, but endpoint
  authentication still belongs to the operator.
- Resolution: Qualification uses `imac@imac.local` from a short-lived
  agent-forwarded ThinkPad session. The endpoint host key was accepted, and no
  private key was copied to the ThinkPad.
- Remaining caveat: The operator must have the existing endpoint key loaded in
  the forwarded agent during playback qualification.

## 6. SSH Playback Initially Reached A Null Sink

- Symptom: The synthesis command returned success twice, but the reviewer heard
  nothing through Sonos.
- Diagnosis: `paplay` ran as the administrative `imac` SSH account, whose
  PulseAudio default was `auto_null`. The physical route belongs to the
  separately logged-in `cortex-endpoint` session.
- Resolution: Added a root-owned qualification helper that rejects arguments,
  relays WAV from standard input through a pipe owned by `cortex-endpoint`, and
  runs through one command-specific passwordless sudo rule. The qualification
  command now uses that helper rather than direct `paplay`.
- Remaining caveat: The corrected Piper and Pocket TTS runs were audible
  through Sonos. The two earlier silent attempts remain excluded because they
  reached `auto_null`, not the endpoint.

## 7. USB Microphone Attachment Changed The Default Output

- Symptom: The first audible Piper sample and Raspotify both played through the
  Anker conference speaker instead of the Sonos line-in.
- Diagnosis: PulseAudio selected the newly attached USB audio card as its
  default sink. Playback relied on that mutable default even though microphone
  input and room output belong to different devices.
- Resolution: Added one endpoint audio-route command that requires exactly one
  PCI analog sink, makes it the PulseAudio default, and returns its name.
  Kiosk startup applies it, Raspotify passes it as `LIBRESPOT_DEVICE`, and the
  qualification helper passes it explicitly to `paplay`. Microphone sources
  remain untouched.
- Remaining caveat: Piper and the selected Pocket TTS are confirmed through
  Sonos, and the final Raspotify pass also reached Sonos rather than the Anker.

## 8. The Analog Master Baseline Was Too Low For Qualification

- Symptom: Playback completed against the pinned built-in analog sink, but the
  reviewer heard nothing and recalled that the physical Master control needs
  to be 80% in this room.
- Diagnosis: Full provisioning restored Master to 70%, while focused media
  provisioning did not previously restore mixer or Pulse sink levels.
- Resolution: Focused media provisioning now restarts the kiosk and Raspotify
  before storing the room baseline of Master 80% unmuted, built-in Speaker
  muted, and rear Headphone 60% unmuted. The shared audio-route command selects
  and unmutes the analog sink without setting its volume.
- Remaining caveat: The reviewer accepted the 80% Master / 60% Headphone
  baseline and confirmed the speech replay through Sonos.

## 9. Keep Volume Keys At The Endpoint Boundary

- Symptom: Qualification exposed a need for quick room-volume adjustment from
  the attached keyboard.
- Diagnosis: A client or coordinator action would add network and
  acknowledgement machinery for a value owned entirely by the iMac analog
  output.
- Resolution: Openbox owns fixed `Ctrl`+`Alt`+arrow bindings and invokes one
  helper that accepts only `up` or `down`, resolves the pinned PCI analog sink,
  and adjusts its PulseAudio volume by 5 percentage points.
- Remaining caveat: The reviewer confirmed both directions, repeat behavior,
  and the existing shortcuts during the final pass.

## 10. Direct ALSA Increases Fought The Active Pulse Sink

- Symptom: `Ctrl`+`Alt`+`Down` lowered output, but `Ctrl`+`Alt`+`Up` could not
  raise it above the 60% baseline.
- Diagnosis: The shortcut wrote the hardware `Headphone` control underneath
  the active PulseAudio sink. PulseAudio still owned the application-facing
  volume and could restore or cap external ALSA changes.
- Resolution: The shortcut now resolves the already pinned PCI analog sink and
  changes that PulseAudio sink by `+5%` or `-5%`. Boot provisioning remains
  responsible for the 80% Master and 60% Headphone physical baseline.
- Remaining caveat: Confirmed in both directions with real playback.

## 11. The Installed Whisper Executable Missed Its Private Library

- Symptom: The same Anker sample reached Vosk, but whisper.cpp qualification
  failed before emitting a summary.
- Diagnosis: `whisper-cli` was dynamically linked to `libwhisper.so.1`, while
  installation copied only the executable from the temporary build tree.
- Resolution: The installer now sets `BUILD_SHARED_LIBS=OFF` and rejects the
  installed executable if `ldd` reports any unresolved library.
- Remaining caveat: The candidates were reinstalled, the executable was
  verified with `ldd`, and the real-room comparison was repeated successfully.

## 12. Short Remote Capture Windows Could Miss The Spoken Phrase

- Symptom: One weather sample measured near silence and produced no useful Vosk
  result while Whisper returned incorrect text. A separate expected audible
  cue was not heard, so speech started outside the short capture window.
- Diagnosis: The operator could not reliably align speech with the remote
  command start and fixed-duration capture from another screen.
- Resolution: Extended the qualification helper to the product's 15-second
  maximum and recorded signal RMS and peak before accepting a sample. The
  repeated weather and lighting samples had healthy levels and zero word
  errors from both recognizers.
- Remaining caveat: The near-silent samples are excluded from accuracy totals
  but retained as failure evidence. The final held browser gesture passed with
  visible signal-level feedback.

## 13. Native Browser Timers Require Their Window Receiver

- Symptom: The first real held shortcut immediately showed `Couldn’t capture.`
  with `Illegal invocation` instead of entering the listening state.
- Diagnosis: `VoiceCapture` stored Chromium's native `setTimeout` and
  `clearTimeout` functions as object properties. Calling those properties used
  the capture object as their receiver, which Chromium rejects before the
  capture timer can start.
- Resolution: Default timer dependencies are receiver-safe wrappers that call
  the native functions through `globalThis`. A regression test substitutes
  receiver-sensitive browser timers and confirms both retain the global
  receiver.
- Remaining caveat: The corrected compact-bar client is deployed; held capture,
  release, cancellation, failure, and recovery all passed in the room.

## 14. The Attached Keyboard Uses Its Distinct Alt Key

- Symptom: The listening instruction named Option, but the attached keyboard's
  Option key did not start capture; its distinct Alt key with Control did.
- Diagnosis: The implemented and tested browser contract is the `altKey`
  modifier exposed by the physical Alt key on this keyboard. The UI copy used
  an Apple-keyboard label that did not match the deployed hardware.
- Resolution: The visible instruction now names Control, Alt, and Space,
  matching the exact accepted shortcut and the issue documentation.
- Remaining caveat: Release-order testing passed with the revised bottom bar.

# Heatmap

## Hot

### H1 - Make Hold State The Capture Authority

- Decision: One request-ID-owned media stream exists only while exact
  `Ctrl`+`Alt`+`Space` remains held.
- Where: `coordinator/client/src/voice-capture.js` and `App.jsx`.
- Why: The microphone must not become a toggle or survive a focus, permission,
  async-resolution, or component-lifecycle boundary.
- Alternatives: Toggle capture; background stream reuse; fixed recording
  duration; voice activity detection.

### H2 - Scope Unattended Permission To One Origin

- Decision: Generate the current secure-context override and audio allowlist
  from the provisioned coordinator origin.
- Where: `endpoint/imac/provision-host`.
- Why: Kiosk capture cannot wait for an interactive prompt, while wildcard or
  global media approval would broaden a private sensor boundary.
- Alternatives: TLS migration in this issue; wildcard policy; global
  command-line media flag; endpoint capture daemon.

### H3 - Keep Only Two Product Speech Contracts

- Decision: Product code exposes one `Recognizer` and one `Synthesizer`
  protocol; candidate adapters and the qualification environment do not become
  runtime configuration.
- Where: `coordinator/speech.py`, `speech-candidates.json`, and the isolated
  qualification installer.
- Why: Engines remain replaceable without preserving a plugin system or
  leaking model objects into coordinator behavior.
- Alternatives: Permanent backend registry; engine-specific coordinator calls;
  hosted speech.
