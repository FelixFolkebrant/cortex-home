# VOI-004: Establish Continuous Voice Sessions

# What

- **Explicit sessions** - Replace held one-shot capture with a visibly active,
  person-started and person-ended voice session.
- **Local turns** - Detect sustained speech and natural pauses locally without
  retaining inactive-session audio.
- **Owned work** - Carry one session ID and increasing turn epochs through the
  browser, coordinator, and Node child.

Before:

- `Ctrl`+`Alt`+`Space` captured one bounded utterance only while held. Each
  answer was isolated behind a request ID.

After:

- `Ctrl`+`Alt`+`Space` starts or ends a continuous session; `Escape`, focus
  loss, reconnect, capture failure, and cleanup also end it.
- The browser submits a turn only after local speech detection observes 400 ms
  of voiced audio followed by 850 ms of silence.
- The coordinator accepts only the next turn epoch for the active endpoint
  session and rejects stale, replaced, cancelled, or malformed work.

## Out Of Scope

- Persistent Pi dialogue, streamed output, synthesis queues, and real
  playback-aware barge-in; VOI-007 and VOI-008 own these.
- Tool calls, room authority, wake words, passive capture, recordings,
  transcripts, durable history, or provider-content logging.
- Treating the provisional detector as room-qualified before the IdeaPad and
  iMac/Sonos passes have been measured.

# Heatmap

### H1 - Session and epoch ownership

- Decision: The coordinator owns one endpoint-bound session and accepts only
  its next positive turn epoch.
- Proposed approach: The browser creates and ends the session through
  `/api/voice/sessions/<session-id>` and labels each WAV with its session and
  epoch; the coordinator and Node child validate the pair before publishing.
- Why: A late capture, child response, endpoint replacement, or reconnect must
  never affect a replacement session.
- Alternatives: Keep request IDs only; let the browser or child own epochs;
  permit parallel turns.
- Review focus: cancellation order, stale event rejection, and replacement
  behavior.

### H2 - Provisional local detector

- Decision: Use browser echo cancellation/noise suppression with RMS >= 0.018,
  a 400 ms speech minimum, and an 850 ms end pause.
- Proposed approach: Keep only the candidate turn in memory and suspend turn
  detection while the current complete-answer path is processing or playing.
- Why: It gives an inspectable initial session path without allowing assistant
  playback to create turns before barge-in is designed.
- Alternatives: Fixed-duration capture; server-side detection; enable capture
  during playback before qualification.
- Review focus: false-turn and pause-latency evidence from the real room.

# How to test

### Explicit session and ordinary turns

- **Start** - Install client dependencies once with `pnpm --dir
  coordinator/client install --frozen-lockfile`, then run
  `./coordinator/develop` and open `http://127.0.0.1:5173` on the IdeaPad.
- **Action** - Press `Ctrl`+`Alt`+`Space`, speak several ordinary sentences with
  natural pauses, then press the shortcut again or `Escape`.
- **Expected** - “Listening” and the browser microphone indicator appear only
  while active. A valid turn moves from “Hearing you” through processing and
  returns to listening without displaying spoken words. Ending removes the
  microphone indicator and shows “Voice session ended.”

### Room noise, playback, recovery, and keyboard operation

- **Start** - Use the room endpoint in both wide and narrow layouts.
- **Action** - Operate only with the keyboard amid ordinary room noise; play a
  local assistant-output sample; then reload or disconnect the endpoint,
  reconnect, and start a new session. Repeat after denying and restoring
  microphone permission.
- **Expected** - Record only aggregate accepted turns, false turns, and
  pause-to-turn latency. No turn begins while an answer is processing or
  playing. An old session cannot affect the new one, permission failure is
  clear, and a restored permission permits a fresh session. Diagnostics and
  logs contain numeric data only, never audio or spoken content.

# Notes

- **Implemented path** - `voice-capture.js` owns the active 16 kHz browser
  stream and discards sub-threshold candidates. `cortex_home.py` owns session
  state and SSE; `agent_runtime.py` and `answer-child.js` validate session and
  epoch propagation.
- **Automated confirmation** - `python3 -m unittest discover -s
  coordinator/tests` passed 143 tests; agent tests/check passed 10 tests; client
  tests/check/build passed 77 tests and a production build. Expected malformed
  HTTP diagnostics appeared during the Python suite.
- **Current limitation** - The detector is not room-qualified and pauses during
  answer processing/playback. VOI-008 owns playback-aware barge-in and its
  physical qualification.
