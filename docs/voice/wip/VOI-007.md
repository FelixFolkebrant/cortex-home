# VOI-007: Stream Active-Session Dialogue

# What

- **Session dialogue** - Keep one coordinator-supervised Pi Agent Core process
  for the active VOI-004 voice session.
- **Bounded context** - Retain only a defined in-memory window of that active
  session's conversation.
- **Early speech** - Stream useful answer text into the current-turn local
  synthesis queue before the provider response completes.

Before:

- Every accepted VOI-004 turn starts a fresh child, sends no conversation
  history, and waits for one complete answer WAV before browser playback.

After:

- One active session owns one bounded dialogue process and context window.
- Current-turn text deltas safely feed local synthesis in order; ending,
  replacement, disconnect, or cancellation destroys the process, queue, and
  history.

## Out Of Scope

- Playback-aware barge-in, acoustic echo qualification, and speech during
  playback; VOI-008 owns those.
- Tools, room authority, wake words, passive capture, durable transcripts,
  recordings, or provider-content logging.
- Changing the selected provider, model, speech engines, or VOI-004 turn
  detector without measured evidence.

# Heatmap

### C1 - Active-session history bound

- Decision: Set the maximum in-memory dialogue context before the first
  provider request.
- Options: A fixed count of recent exchanges; a fixed text-character budget;
  a combined exchange and character limit.
- Impact if wrong: An overly small bound makes follow-ups unreliable; an
  overly large one expands provider exposure, latency, and memory use.
- Proposed choice: Combined explicit exchange and character limits, with the
  oldest complete exchange removed before every provider request.
- Why: It gives a predictable privacy and latency boundary while retaining
  recent conversational meaning.
- Status: open

### H1 - Coordinator-owned dialogue lifecycle

- Decision: The coordinator starts one Node dialogue process after session
  activation and owns all process termination.
- Proposed approach: Bind the process to the accepted VOI-004 session ID;
  accept one completed epoch at a time; terminate it before an endpoint
  replacement, disconnect, session end, or cancellation can publish stale work.
- Why: Pi must not become the authority for session identity, cancellation, or
  device lifecycle.
- Alternatives: Start a fresh process every turn; make the browser own history;
  run a shared dialogue service.
- Review focus: process cleanup, epoch ownership, and history disposal.

### H2 - Stream-to-synthesis boundaries

- Decision: Queue only ordered, bounded useful text segments for local speech.
- Proposed approach: Hold incomplete fragments until a safe punctuation or
  length boundary, synthesize sequentially, and discard queued/current audio
  when the epoch becomes stale.
- Why: Early audio should improve response feel without choppy speech or stale
  playback.
- Alternatives: Wait for the complete answer; synthesize every delta; delay all
  speech until playback-aware barge-in exists.
- Review focus: segment quality, queue ownership, and cancellation races.

# How to test

### Follow-up dialogue

- **Start** - Start an explicit VOI-004 session on the IdeaPad local room, then
  use the implemented dialogue runtime.
- **Action** - Ask an ordinary question, then a follow-up that relies on the
  immediate prior exchange. End the session and start a new one before asking a
  similar follow-up.
- **Expected** - The active session resolves the follow-up from its bounded
  in-memory context. The new session has no knowledge of the old one, and no
  spoken content appears in the UI, logs, or durable storage.

### Streaming and lifecycle safety

- **Start** - Use an active session with diagnostics visible.
- **Action** - Ask for a response, then end the session, replace the endpoint,
  or simulate a provider failure while text/audio work is in flight.
- **Expected** - Useful local speech begins before the final provider response
  when a safe segment is available. After a terminal session event, no old text,
  synthesis, or playback can resume; the display shows a content-free failure
  or return to listening as appropriate.

# Notes

- **Dependency** - VOI-004 provides the explicit microphone lifetime, local
  turn boundaries, session ID, and monotonic epoch ownership this issue reuses.
- **Local development** - Extend `coordinator/development.py` only enough to
  exercise the real session protocol without a provider key or room hardware.
- **Follow-on** - VOI-008 will keep VOI-004 detection active during thinking
  and playback, canceling this issue's current stream and synthesis queue on a
  new user turn.
