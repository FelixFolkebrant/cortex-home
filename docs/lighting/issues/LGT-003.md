# Implementation Walkthrough

## 1. Resolve And Observe The Scene Catalog

`coordinator/hue.py` still resolves exactly one room named `Rum`, but now
collects every scene whose Hue group is that room. It rejects an empty catalog,
empty names, and names duplicated without regard to case. Scene resources stay
inside the adapter and are exposed only through their human-facing names.

The catalog is sorted case-insensitively. One subscription to Hue scene
resource updates refreshes the catalog and computes the active subset. Both
`static` and `dynamic_palette` count as active. Zero active scenes means Hue
does not recognize the current lamp values as an exact scene; multiple active
scenes remain multiple rather than being collapsed to one guess.

An available adapter snapshot is:

```json
{
  "status": "available",
  "scenes": ["Bright", "Relax", "Warm"],
  "activeScenes": ["Relax"]
}
```

Disconnect, invalid catalog state, or shutdown publishes the same fields with
`status: "unavailable"` and empty arrays. Reconnection refreshes from the live
bridge without another link-button press.

## 2. Publish And Activate Exact Names

`coordinator/cortex_home.py` timestamps the normalized adapter snapshot,
suppresses unchanged state, publishes changes as `room.lighting`, and sends the
latest state on every endpoint connection.

`room.scene.activate` now requires one exact scene name from the current
available catalog:

```sh
curl \
  --fail-with-body \
  --header 'Content-Type: application/json' \
  --data '{"requestId":"relax-1","action":"room.scene.activate","scene":"Relax"}' \
  http://<server-host>:8080/api/actions
```

The accepted and terminal action payloads include the safe scene name. The
adapter resolves that name to its private Hue resource, subscribes before the
recall, and completes only after a later aggregate observation includes the
requested name. Endpoint disconnection does not cancel the Hue-owned action.

The response remains bounded by the existing action timeout and distinguishes:

| HTTP | Code | Meaning |
|---|---|---|
| 400 | `invalid_scene` | The name is missing or absent from the available catalog |
| 503 | `scene_unavailable` | Hue or the selected catalog resource became unavailable |
| 504 | `scene_timeout` | The requested name was not observed active in time |
| 502 | `scene_failed` | Hue rejected the recall |

Use the renamed dependency-free verifier for one exact live name:

```sh
./coordinator/verify_scene.py <server-host> 'Relax'
```

It requires safe connected health, generates a request ID, submits the named
action, and passes only after the exact completed response returns.

## 3. Display And Cycle Scenes

`coordinator/client/src/music.js` keeps lighting independent from Today,
playback, channel, connection, and interaction state. Its fixed keyboard
classifier accepts:

- `Ctrl`+`Alt`+`1` for Today;
- `Ctrl`+`Alt`+`2` for Music; and
- `Ctrl`+`Alt`+`S` for the next scene.

The scene shortcut uses physical `KeyS`. After exactly one active scene it
selects the following catalog name and wraps after the last. With custom
lighting or multiple active scenes it starts at the first name. It does nothing
when scene state is unavailable, a visible action is active, the key repeats,
or Shift or Meta is also pressed.

`coordinator/client/src/App.jsx` shows the shared scene badge above either
channel:

- `Scenes unavailable`;
- `Custom lighting`;
- `<name> active`; or
- the complete `name + name` active list.

Scene working, completion, and failure overlays name the requested scene. The
client posts only its name to the coordinator and never contacts Hue.

## 4. Deploy And Recover

Deploy through the unchanged entry point:

```sh
./coordinator/install homelab
```

The installer rebuilds the client, deploys the coordinator and Hue adapter,
recreates the isolated Python environment, and restarts
`cortex-home.service`. It preserves `/etc/cortex-home/hue.json`; no migration,
new credential, or re-pair is required.

Confirm safe service state:

```sh
curl --fail-with-body http://<server-host>:8080/api/health
```

If scene state is unavailable while Hue health is connected, confirm that
exactly one room is named `Rum` and that its scene names are non-empty and
unique without regard to case. Correct the catalog in native Hue, then restart
the coordinator:

```sh
ssh homelab 'sudo systemctl restart cortex-home.service'
```

For a bridge or event-stream interruption, restore Hue connectivity and wait no
more than 60 seconds. The adapter should reconnect with the existing credential
and republish the live catalog without replaying an earlier scene request.

# Heatmap

## Hot

### H1 - Use Unique Scene Names As The Product Boundary

- Decision: Publish every uniquely named scene from exact room `Rum` and accept
  one exact current name in `room.scene.activate`.
- Where: `coordinator/hue.py` and `coordinator/cortex_home.py`.
- Why: Scene names are the human-facing vocabulary the display, keyboard, and
  future voice agent share, while Hue resource IDs stay private.
- Alternatives: Keep only `Warm`; expose IDs; silently select duplicates;
  configure aliases or fuzzy matching in the coordinator.

### H2 - Preserve Aggregate Observed Activity

- Decision: Publish ordered `scenes` and `activeScenes` arrays with explicit
  availability instead of forcing one current scene.
- Where: Hue adapter, coordinator `room.lighting`, and the shared client badge.
- Why: Native controls can produce zero or multiple active scene reports, and
  the system should not guess at physical state.
- Alternatives: Publish one nullable name; select the first active scene; infer
  state from individual lamp values.

### H3 - Cycle Deterministically

- Decision: Cycle through case-insensitively ordered names, advance after one
  active scene, wrap, and start at the first name for zero or multiple active
  scenes.
- Where: `nextScene` in `coordinator/client/src/music.js`.
- Why: One fixed keyboard gesture remains predictable without storing another
  order or adding a scene picker.
- Alternatives: Provider order; recent-use order; previous and next shortcuts;
  refuse ambiguous starting states.
