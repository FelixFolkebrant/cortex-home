# AIR-002: Stabilize iPhone rotation mirroring

# What

Make the iMac UxPlay receiver tolerate an iPhone changing between portrait and
landscape while mirroring.

Before:

UxPlay accepted GStreamer's automatic H.264 decoder, timestamp
synchronization, and video-sink selection. On the older X11 iMac, rotating the
iPhone can leave the mirror on a stale frame or visibly glitching.

After:

The receiver uses UxPlay's software H.264 decoder (`-avdec`), disables
timestamp synchronization (`-vsync no`), and selects the installed X11 XVideo
sink (`-vs xvimagesink`). Provisioning explicitly installs the libav GStreamer
plugin that supplies the decoder.

## Out Of Scope

- Replacing UxPlay, upgrading its Ubuntu package, or adding a new casting
  protocol.
- Configuring a hardware video decoder or another video sink.
- Changing the on-demand AirPlay lifecycle, privacy boundary, or audio route.

# Heatmap

- **Decoder choice** — software decoding trades some CPU for reliable decoder
  reconfiguration when an iPhone changes orientation. The existing iMac moving
  mirror sample is the acceptance check.

# How to test

### Rotating mirror

- **Start** - Deploy the focused media configuration with
  `./endpoint/imac/provision-media`, then open AirPlay and turn its receiver on.
- **Action** - Mirror an iPhone to `Skärmen`, rotate portrait → landscape →
  portrait several times during a moving screen share, then end mirroring and
  reconnect once.
- **Expected** - Every orientation change continues updating without a frozen
  last frame or visual corruption. The native mirror remains borderless and
  full-screen, audio remains on the shared Sonos route, and the receiver is
  ready for the reconnect.

### Provisioned decoder

- **Start** - After the focused deployment completes.
- **Action** - On the iMac, run `gst-inspect-1.0 avdec_h264` and start the
  AirPlay receiver.
- **Expected** - The libav H.264 decoder is installed and UxPlay starts
  normally.

# Notes

- The endpoint's committed configuration installs an X11/Openbox session with
  the Radeon driver and `gstreamer1.0-x`; this rules out the Wayland and NVIDIA
  variants. A non-interactive SSH probe could not authenticate from this
  workspace, so the physical qualification above remains required.
- UxPlay 1.68 supports all three selected options. Its upstream documentation
  recommends `-avdec` when accelerated H.264 decoding is incorrectly configured
  and `-vsync no` for screen mirroring.
- `gstreamer1.0-libav` is added to both full and focused provisioning so
  `-avdec` never depends on a transitive package choice.
